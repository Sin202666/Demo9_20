# 模块规范性审查检查清单

审查时逐项对照，在报告中按九大类汇总。规范出处：`docs/代码结构和设计开发规范.md`（下称 **结构**）、`docs/代码注释和说明开发规范.md`（下称 **注释**）、`docs/文本本地化开发规范.md`（下称 **本地化**）。

---

## 1. 架构与分层

| # | 检查项 | 依据 |
|---|--------|------|
| 1.1 | 文件位于正确目录，职责与层级匹配 | 结构 §1.2 |
| 1.2 | 无跨层逻辑（如 System 写 UI、GuiScripts 改权威数据） | 结构 §1.2–1.3 |
| 1.3 | Manager 仅编排/路由，无复杂业务、无直接 DataStore | 结构 §1.3 |
| 1.4 | 业务模块未用 `IsServer` / `RunService:IsServer()` 承载双端逻辑 | 结构 §1.4 |
| 1.5 | System 未直接操作 UI Instance | 结构 §1.3 |
| 1.6 | `ReplicatedStorage/Msg` 下无业务脚本 | 结构 §1.2 |
| 1.7 | 单一职责：模块名不隐含多个无关领域 | 结构 §3.2 |
| 1.8 | **P0**：无客户端权威结算（发奖/伤害/击杀/掉落/任务完成不以客上报为最终事实）；发现须严正警告 | 结构 §1.6 |
| 1.9 | **P0**：同一实体位姿/速度/WalkSpeed 无逻辑不明确的多源头抢写；新写口须经已有合成器/仲裁器 | 结构 §1.7 |
| 1.10 | **P0（方案/开工）**：非豁免项须二次审评通过且需求方同意后再改业务代码；初稿不得当开工许可 | 结构 §1.8 |

## 3. 模块结构与封装

| # | 检查项 | 依据 |
|---|--------|------|
| 3.1 | 区块顺序：头注释 → 服务 → 模块引用 → `local M = {}` → 常量 → 私有变量 → 私有函数 → 公共函数 → Init → return | 结构 §3.3；注释 §1.1 |
| 3.2 | 模块范式匹配（类 / 单例 / 纯函数库） | 结构 §3.1 |
| 3.3 | 私有函数 `local function _name`，未挂到 module 表 | 结构 §3.6；注释 §1.4 |
| 3.4 | 未直接暴露可变内部表；配置/查询 API 返回深拷贝而非原表引用 | 结构 §3.6 |
| 3.5 | `Init()` 由 Manager 调用；业务模块间不互调 `Init()` | 结构 §3.5；注释 §1.5 |
| 3.6 | `Init()` 仅绑事件/定时器，无版本迁移 | 结构 §3.5、§3.7、§5.1 |
| 3.7 | 类模块有 `new()` + `destroy()`，连接在 destroy 或玩家离开时断开 | 结构 §3.4、§6.4 |
| 3.8 | 单文件有效代码行 >500（排除纯注释行与空行）或有理由说明；重复逻辑 >2 处应抽取 | 结构 §3.7 |
| 3.9 | 无 `Initialize` 等非统一初始化命名 | 注释 §1.6 |

| # | 检查项 | 依据 |
|---|--------|------|

## 5. 注释与文档

| # | 检查项 | 依据 |
|---|--------|------|
| 5.1 | System/ToolSystem/复杂模块/Manager 有完整文件头（Module、Description、Author、Created、Last Modified 五项必填） | 注释 §2.1 |
| 5.1a | 文件头使用说明应尽量详细（功能、模块关系、加载方式、典型示例等；复杂模块参考 AssetAcquire） | 注释 §2.1.1 |
| 5.1b | **P0**：新建或本次改写文件头时，`Author` 必须等于 `git config user.name`；禁止 `Agent`/`Cursor`/`AI` 等工具名；`user.name` 未配置不得臆造 | 注释 §2.1.0 |
| 5.2 | 长模块（≥80 行）有分区注释（`====` 分隔） | 注释 §2.2 |
| 5.3 | **所有**私有函数有块注释（首行描述必填） | 注释 §2.3 |
| 5.4 | 有参/返回值时私有函数含完整 `@param` / `@return`（`名称 类型 - 语义说明`，禁止仅写类型或仅写名称） | 注释 §2.3.1 |
| 5.5 | 公共 API（System/ToolSystem/Manager）**必须**有块注释；每个 `@param` / `@return` 含类型与 `-` 后语义说明；`any`/`table` 须补充字段或取值说明 | 注释 §2.3.1 |
| 5.6 | 行内注释解释「为什么」，非复述代码 | 注释 §2.4 |
| 5.7 | 复杂逻辑/算法/存档规则有额外说明 | 注释 §2.5 |
| 5.8 | 无注释掉的废弃代码；TODO 格式 `-- TODO(作者, 日期):` | 注释 §2.6 |

## 6. 通信与校验

*适用于 System、Manager、含 Remote 处理的模块。*

| # | 检查项 | 依据 |
|---|--------|------|
| 6.1 | System 未私自 `Connect` Remote；提供处理函数由 NetWorkManager 路由 | 结构 §4.1 |
| 6.2 | 服务端 Remote 处理校验顺序：玩家 → 数据 → 业务 → 频率 → 异常 | 结构 §4.2 |
| 6.3 | Remote 失败静默 return + Log，不向客户端泄露内部错误 | 结构 §7.2 |
| 6.4 | RemoteFunction 有 pcall、在线检查；非必要不用 | 结构 §4.4 |
| 6.5 | BindableEvent 未滥用替代简单直接调用；未用于跨端 | 结构 §4.5 |
| 6.6 | 同端通信方式合理（直接调用 vs 事件） | 结构 §4.3 |

## 9. 文本本地化

*适用于 GuiScripts、含玩家可见文案的客户端模块。纯服务端无 UI 写「不适用」。日志与注释中的中文不计入。*

| # | 检查项 | 依据 |
|---|--------|------|
| 9.1 | 玩家可见文案走 `TranslationHelper.SetText` / `TranslateByKey`，未在代码里写死展示句 | 本地化 §6、§9 |
| 9.2 | 传给本地化 API 的 Key 仅为调用处字符串字面量，或配置表 `Zh*` 字段；无 `cfg.Des` / 自建 `KEYS[x]` / 先赋变量再传入 | 本地化 §6.2.1、§9 |
| 9.3 | 新 Key 已同步写入 `config/Localization/LocalizationTable.xlsx`；未手改 `Language.luau` / `ConfigInstance.luau` | 本地化 §2、§4、§9 |
| 9.4 | 可变数字/数量用 `{1}` 占位 + `args` 数组下标；未用 `SetText` 第四参 `addText` 拼接会随语言丢失的内容 | 本地化 §6.1、§9 |
| 9.5 | 纯数字、玩家名、已拼好展示串使用 `SetRawText` / `SetText_UnTrans` | 本地化 §6.1、§9 |
| 9.6 | 静态 UI：标签 `本地化` + 实例 `Name` = Key；克隆列表未依赖模板残留的 `代码本地化` 冲掉后缀 | 本地化 §6.3、§7 |

## 严重程度参考

| 级别 | 典型项 |
|------|--------|
| 🔴 必须修复 | 分层错误、IsServer 混写、私自监听 Remote、直接写 DataStore、Init 内版本迁移、绕过 Utils、业务代码中 `Utils.X` 链式调用未顶部缓存、**对外返回配置/缓存原表引用可篡改**、导出私有 API、私有函数完全无注释（System/ToolSystem）、缺文件头或文件头缺必填字段（System/ToolSystem/复杂模块/Manager）、**新建/改写文件头时 Author 未对齐 `git config user.name` 或使用工具/助手名**（注释 §2.1.0）、公共 API 或私有函数 `@param`/`@return` 缺 `-` 后语义说明（System/ToolSystem/Manager）、**客户端权威结算**（结构 §1.6）、**多源头抢写位姿/速度等权威字段**（结构 §1.7）、**方案未二次审评通过即开工**（结构 §1.8）、**玩家可见文案硬编码、Key 非字面量/非 Zh*、手改 Language.luau/ConfigInstance.luau**（本地化 §9） |
| 🟡 建议改进 | 结构顺序错乱、公共 API 缺注释、返回值不一致、函数过长、魔法数字、缺 destroy 断开连接、文件头使用说明过于简略（复杂/多 API 模块）、用 `addText` 拼接可变数字、克隆模板残留 `代码本地化` |
| 🟢 可选优化 | 缺分区注释（<80 行）、可抽取重复逻辑、命名可更清晰 |
