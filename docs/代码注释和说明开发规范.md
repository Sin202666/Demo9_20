## 一、模块脚本书写细则

主文档 [3.3 模块内部结构](./CODING_STANDARDS.md#33-模块内部结构固定顺序) 已定义固定顺序；本节补充完整模板、文件命名、依赖与导出细则。

### 1.1 完整模块模板

以下模板适用于 **单例服务**（System / ToolSystem）。类模块与纯函数库见主文档 [3.1 模块范式](./CODING_STANDARDS.md#31-模块范式)。

```lua
--[[
    Module: SystemBag
    Description: 背包领域业务逻辑
    Author: Team Name
    Created: 2024-01-15
    Last Modified: 2024-01-20

    功能：
    - 物品增删查
    - 背包容量校验
]]

-- ========================================
-- 服务引用
-- ========================================
local Players = game:GetService("Players")

-- ========================================
-- 模块引用
-- ========================================
local Utils = require(game.ReplicatedFirst.AllSideCode.UtilsSystem)
local Log = Utils.Log
local EnumMgr = Utils.EnumMgr

-- ========================================
-- 模块定义
-- ========================================
local SystemBag = {}

-- ========================================
-- 常量定义
-- ========================================
local MAX_BAG_SIZE = 100

-- ========================================
-- 私有变量
-- ========================================
local _initialized = false

-- ========================================
-- 私有函数
-- ========================================
--[[
    校验玩家对象是否有效

    @param player Player - 玩家对象
    @return boolean - 是否有效
]]
local function _validatePlayer(player)
    return player and player:IsA("Player")
end

-- ========================================
-- 公共函数
-- ========================================
function SystemBag.AddItem(player, itemId, count)
    if not _validatePlayer(player) then
        return false, "INVALID_PLAYER"
    end
    -- ...
    return true
end

-- ========================================
-- 初始化
-- ========================================
function SystemBag.Init()
    if _initialized then return end
    _initialized = true
    -- 绑事件、启动定时器
end

return SystemBag
```

**结构顺序（与主文档一致）：**

| 顺序 | 区块 | 说明 |
|------|------|------|
| 1 | 文件头注释 | 模块名、用途、作者、创建/修改日期（五项必填）；**应尽量**补充使用说明（功能、模块关系、示例等，见 §2.1.1） |
| 2 | 服务引用 | `game:GetService` |
| 3 | 模块引用 | 通过 `UtilsSystem` 或直接 `require` 子模块 |
| 4 | 模块定义 | `local ModuleName = {}` |
| 5 | 常量 | `UPPER_SNAKE_CASE` |
| 6 | 私有变量 | 下划线前缀 |
| 7 | 私有函数 | `local function _name`，**须附带块注释**（见 PART2 §2.3） |
| 8 | 公共函数 | `ModuleName.FuncName` |
| 9 | 初始化 | `Init()` 或延迟 `_init()` |
| 10 | `return` | 返回模块表 |

### 1.2 文件命名

| 规范 | 示例 |
|------|------|
| PascalCase，与模块名一致 | `SystemBag.luau`、`CfgFind.luau` |
| 多文件 System 使用目录 + `init.luau` | `SystemSave/init.luau` |
| 类型定义后缀 | `Bag-Type.luau`（放 `Interface/`） |

```
✅ 正确：
- SystemBag.luau
- DataService.luau
- SystemSave/init.luau

❌ 错误：
- systemBag.luau       -- 应使用 PascalCase
- data_service.luau    -- 不应使用下划线
- player-manager.luau  -- 不应使用连字符
```

文件名必须与 `Utils` 访问键一致（如 `SystemBag.luau` → `Utils.SystemBag`），见主文档 [2.2 模块注册位置](./CODING_STANDARDS.md#22-模块注册位置)。

### 1.3 模块引用与依赖

```lua
-- ✅ 正确：顶部声明，通过 UtilsSystem 访问
local Utils = require(game.ReplicatedFirst.AllSideCode.UtilsSystem)
local SystemSave = Utils.SystemSave
local Log = Utils.Log

-- ✅ 正确：同目录子模块
local SaveMetaData = require(script.SaveMetaData)

-- ✅ 正确：名称过长时使用别名
local PM = Utils.PlayerManager

-- ❌ 错误：函数内部 require
function SystemBag.AddItem(player, itemId)
    local Log = Utils.Log  -- 应在文件顶部
end

-- ❌ 错误：绕过 UtilsSystem 长路径 require
local SystemBag = require(game.ServerStorage.ServerSideCode.System.SystemBag)
```

循环引用处理见主文档 [2.6 循环引用处理](./代码结构和设计开发规范.md#26-循环引用处理)。

### 1.4 导出与封装

```lua
-- ✅ 正确：只导出公共接口
local SystemBag = {}

local function _validatePlayer(player)
    return player and player:IsA("Player")
end

function SystemBag.AddItem(player, itemId, count)
    -- ...
end

return SystemBag

-- ❌ 错误：导出私有成员
function SystemBag._validatePlayer = _validatePlayer
```

| 类型 | 规范 |
|------|------|
| 公共函数 | `module.FuncName`，仅暴露外部真正需要的接口 |
| 私有函数 | `local function _funcName`，禁止挂到 `module` |
| 内部数据 | 提供 `GetX` 只读封装，禁止直接暴露可变表；配置类 API 须返回深拷贝 |

详见主文档 [3.6 接口暴露原则](./CODING_STANDARDS.md#36-接口暴露原则)。

### 1.5 初始化约定

| 方法 | 可见性 | 调用方 | 用途 |
|------|--------|--------|------|
| `module.Init()` | 公共 | Manager / 启动链 | 一次性初始化，绑事件 |
| `local function _init()` | 私有 | 模块内部 | 延迟初始化、防重复 |

```lua
-- ✅ 正确：Manager 调用公共 Init
function SystemBag.Init()
    if _initialized then return end
    _initialized = true
end

-- ✅ 正确：首次使用时延迟初始化
function SystemBag.GetCache()
    _init()
    return _cache
end

-- ❌ 错误：业务模块互相调用 Init
function SystemOther.DoSomething()
    Utils.SystemBag.Init()  -- 禁止
end
```

完整约定见主文档 [3.5 初始化方法约定](./CODING_STANDARDS.md#35-初始化方法约定)。

### 1.6 常见反模式

```lua
-- ❌ 错误：组织混乱
local SystemBag = {}
local ReplicatedStorage = game:GetService("ReplicatedStorage")  -- 应在顶部
function SystemBag.DoSomething() end
local _cache = {}  -- 应在模块定义之后、私有变量区

-- ❌ 错误：未 require 就使用
local data = SystemBag.GetData(player)

-- ❌ 错误：对外暴露 Initialize（应统一为 Init）
function SystemBag.Initialize() end
```

## 二、注释规范

注释应解释**为什么**和**非显而易见的约束**，而非复述代码在做什么。命名规范见主文档 [第六章](./CODING_STANDARDS.md#六命名规范)。

### 2.1 文件头注释

每个 System、ToolSystem、复杂工具模块及 Manager **必须**添加文件头。仅当 ToolBasic 为不足 80 行的无状态纯函数库时可省略。

文件头须使用 `--[[ ... ]]` 块注释，置于文件最顶部。

```lua
--[[
    Module: SystemBag
    Description: 背包领域业务逻辑
    Author: Team Name
    Created: 2024-01-15
    Last Modified: 2024-01-20

    功能：
    - 物品增删查
    - 背包容量与装备槽校验
]]
```

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| `Module` | **必须** | 与文件名、模块表名一致 |
| `Description` | **必须** | 一句话说明职责 |
| `Author` | **必须** | 见下方 **P0：Author 对齐 Git 名** |
| `Created` | **必须** | 创建日期，格式 `YYYY-MM-DD` |
| `Last Modified` | **必须** | 最近修改日期，格式 `YYYY-MM-DD`；新建文件可与 `Created` 相同 |
| `功能` 列表 | 可选 | 模块对外能力概要 |

缺任一必填字段、格式不符或 `Module` 与文件名不一致，视为规范违规。

#### 2.1.0 P0：Author 对齐 Git 名

对本仓库中**由当前开发者新建**，或**明确要求填写/更新文件头**的模块，`Author` **必须**等于本机 `git config user.name`（本地配置优先于全局）。审查与提交前自检均按 **P0（必须修复）** 处理。

| 要求 | 说明 |
|------|------|
| 取值来源 | `git config user.name`（勿手写昵称、勿用团队占位名冒充个人作者） |
| 禁止 | `Agent`、`Cursor`、`AI` 或其他工具/助手名 |
| `user.name` 未配置 | **停止**并先配置 Git 身份，禁止臆造作者名 |
| 连带 | 新建或更新此类文件头时，同步 `Last Modified` 为当天 `YYYY-MM-DD` |

历史模块若作者字段为真实团队/个人名且非本次改写文件头，审查时不因「与当前 Git 名不一致」单独升为 P0；一旦本次改写 `Author`/`Last Modified`，则必须对齐当前 Git 名。

#### 2.1.1 使用说明（应尽量详细）

System、ToolSystem、复杂工具模块及 Manager 的文件头，**应尽量**补充可独立阅读的使用说明，使维护者与 AI/Review 者**无需通读实现**即可正确接入。简单、职责单一的模块可只写 `功能` 列表；API 较多、选项组合复杂或与兄弟模块职责重叠时，**必须**写清使用说明。

**建议包含的内容（按模块实际情况选取，不必机械凑全）：**

| 区块 | 说明 |
|------|------|
| 功能 / 能力列表 | 对外提供哪些能力 |
| 与相关模块的关系 | 职责边界、推荐入口（如「业务侧优先 `ResourceUtil`，需精细 options 时用本模块」） |
| 关键参数 / 选项 | 表字段含义、默认值、枚举取值、互斥与优先级 |
| 端侧 / 调用约束 | 仅服务端、须玩家在线、须已加载存档等 |
| 加载方式 | 标准 `Utils` 引用写法 |
| 使用示例 | 1～3 个典型调用（含常见分支，如默认路径、跳过某步骤、对象池等） |

参考范例：`ToolSystem/AssetAcquire.luau` 文件头（功能、模块关系、Scope、Options 优先级、公共 API 一览、示例代码）。

```lua
--[[
    Module: AssetAcquire
    Description: 统一资源获取（路径解析 → Clone → Restore → 可选对象池）
    Author: 中台组
    Created: 2026-07-01
    Last Modified: 2026-07-02

    功能：
    - 按相对路径获取资源实例，默认 Clone + Restore
    - 可选对象池借出

    推荐：业务侧优先 Utils.ResourceUtil；需精细 control options 时用本模块。

    加载方式：
        local Utils = require(game.ReplicatedFirst.AllSideCode.UtilsSystem)
        local AssetAcquire = Utils.AssetAcquire

    使用示例：
        local pet = AssetAcquire.Get("ModelRes/Pet/Cat1")
]]
```

公共 API 的块注释同样**应尽量详细**：除 `@param` / `@return` 外，必要时在首行或 `@return` 中说明副作用、失败形态、与其他 API 的选用关系（见 [2.3](#23-函数注释)）。

### 2.2 分区注释

模块内用统一分隔线划分区块，与 [1.1 完整模块模板](#11-完整模块模板) 顺序一致：

```lua
-- ========================================
-- 服务引用
-- ========================================

-- ========================================
-- 私有函数
-- ========================================
```

- 使用 `====` 分隔线，区块标题简短明确。
- 简单脚本（不足 80 行）可省略分区注释，保持结构顺序即可。

### 2.3 函数注释

**公共函数与私有函数均须附带注释。** 私有函数（`local function _name`）不得省略说明，即使不对外导出，也须让 Review 者与其他维护者快速理解职责与约束。

#### 公共 API

System、ToolSystem、Manager 的**对外公共函数必须**使用块注释，且**每一个** `@param` / `@return` 均须写全类型与语义说明（不得以「名称已自解释」为由省略）。

格式：**`@param 参数名 类型 - 语义说明`**；**`@return 类型 - 语义说明`**。

| 要求 | 说明 |
|------|------|
| 类型 | Luau 类型或 Roblox 类型（`Player`、`number?`、`{number}` 等） |
| 语义说明 | `-` 后写含义、取值范围、枚举引用、默认值、调用端约束 |
| `any` / `table` | **必须**补充字段结构、键名含义或示例 |
| 可选参数 | 类型标 `?`，说明中写默认行为（如「nil 时按 Normal 处理」） |

```lua
--[[
    向玩家背包添加物品

    @param player Player - 目标玩家；须在线且已加载存档
    @param itemId number - CfgFind 配置表物品 ID
    @param count number? - 添加数量；nil 或省略时视为 1
    @return boolean, string? - 成功 true；失败 false 与 UPPER_SNAKE errorCode
]]
function SystemBag.AddItem(player, itemId, count)
    -- ...
end
```

```lua
-- ❌ 错误：仅有类型，无语义说明
-- @param player Player
-- @param key string

-- ❌ 错误：仅有名称，无类型与说明
-- @param player - 玩家

-- ❌ 错误：any 未说明结构
-- @param data any
```

#### 私有函数（必须）

System、ToolSystem 及复杂工具模块中的**每一个**私有函数都必须有块注释，至少包含：

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| 首行描述 | **必须** | 一句话说明函数做什么、在什么场景下调用 |
| `@param` | 有参数则**必须** | 格式 `参数名 类型 - 语义说明`；禁止仅写类型或仅写名称 |
| `@return` | 有返回值则**必须** | 格式 `类型 - 语义说明`；无返回值可写 `@return nil` 或省略 |
| 约束/副作用 | 视情况 | 非显而易见的业务规则、性能考量、调用前提（如「仅加载流程内调用」） |

#### 2.3.1 `@param` / `@return` 书写细则（强制）

适用于 System、ToolSystem、Manager 及复杂工具模块的**公共与私有函数**。

**标准格式：**

```lua
@param paramName Type - 语义说明（含取值/枚举/结构字段）
@return ReturnType - 语义说明
```

**必须补充说明的场景：**

| 场景 | 须写明 |
|------|--------|
| 枚举/常量 | 引用来源，如 `EnumMgr.TipTp.Normal / Error` |
| 翻译键 | 说明为 `LanguageCfg` 键名，非展示文案；完整约定见 [文本本地化开发规范](./文本本地化开发规范.md) |
| 服务端专用 API | 调用端限制，如「仅服务端；客户端调用无效」 |
| 表参数 | 必填字段、字段类型、示例 |
| 可选参数 | nil 时的默认行为 |

```lua
--[[
    下发结构化获得奖励提示

    @param player Player - 接收提示的目标玩家；服务端须已加入游戏
    @param data table - 模板数据，须含 Type（string）；获得奖励时另须 ID（number）、Count（number）
    @return nil
]]
function TipsModule.NewShowTipsTemplate(player: Player, data: { [string]: any })
end
```

```lua
-- ❌ 错误：@return boolean 缺少语义
-- @return boolean

-- ✅ 正确
-- @return boolean - 客户端环境就绪且 LocalPlayer 可用时为 true
```

```lua
--[[
    按 SaveMetaData 补全玩家存档中缺失的字段（结构补全，非版本迁移）

    @param plr Player - 玩家对象
    @return nil
]]
local function _repairPlayerStat(plr: Player)
    -- ...
end

--[[
    从 DataStore 读取指定玩家的原始存档

    @param playerId string - 会话键，格式 "Player{UserId}"
    @return boolean, any? - 读取成功返回 true 与数据；失败返回 false 与错误信息
]]
local function _loadSessionFromStore(playerId: string): (boolean, any?)
    -- ...
end

--[[
    将会话标记为在线并写入内存缓存

    @param playerId string - 会话键
    @param data table - 从 DataStore 加载的存档表
    @return nil
]]
local function _setSessionData(playerId: string, data: any)
    -- ...
end
```

```lua
-- ❌ 错误：私有函数无任何说明
local function _savePlayerStat(plrId: string, isLeave: boolean?)
    -- ...
end

-- ❌ 错误：仅一行行内注释，不足以替代函数块注释
local function _repairPlayerStat(plr) -- 修复玩家数据
    -- ...
end
```

#### 注释要求汇总

| 场景 | 是否必须写注释 |
|------|----------------|
| 私有函数（System / ToolSystem / 复杂工具 / Manager） | **必须**（块注释 + 用途说明；有参/返回值则完整 `@param` / `@return`，格式见 §2.3.1） |
| 对外公共 API（System / ToolSystem / Manager） | **必须**（块注释 + 每个参数/返回值的类型与 `-` 后语义说明） |
| 简单纯函数库（不足 80 行、无业务状态） | 私有函数仍建议注释；仅极 trivial 的单行辅助可酌情省略 |
| 含业务规则、边界条件、性能考量的逻辑 | **必须**（公共与私有均适用） |
| 临时调试代码 | 提交前删除，不保留注释 |

返回值格式须与主文档 [7.2 返回值约定](./CODING_STANDARDS.md#72-返回值约定) 一致。

### 2.4 行内注释

```lua
-- ✅ 正确：解释原因或约束
local damage = baseDamage * multiplier  -- 装备加成已在 multiplier 中折算
if count <= 0 then return false, "INVALID_COUNT" end  -- 防止配置错误导致负数入包

-- ❌ 错误：复述代码
local damage = baseDamage * multiplier  -- 计算伤害
if count <= 0 then return end  -- 如果数量小于等于 0 则返回
```

### 2.5 复杂逻辑注释

除 [2.3](#23-函数注释) 要求的函数块注释外，算法、性能权衡、与策划/存档相关的隐含规则须在**函数描述或行内**进一步注明：

```lua
-- 按 itemId 二分查找（背包已按 id 排序，O(log n)）
local function _findItemSlot(bag, itemId)
    -- ...
end

-- 结构补全：仅填充 SaveMetaData 中缺失字段，不做版本迁移（迁移见 FixData.luau）
local function _repairBagStructure(bagData)
    -- ...
end
```

### 2.6 不宜注释的内容

- 已删除或注释掉的废弃代码（应直接删除，依赖版本控制追溯）。
- TODO 无负责人或日期的悬空项（若保留，格式：`-- TODO(作者, 日期): 说明`）。
- 通过改名即可表达的意图（优先改函数名，而非加注释）。

## 快速检查清单

提交前可对照以下要点自检（与主文档清单互补）：

- [ ] 模块结构顺序符合 [1.1](#11-完整模块模板)；服务与模块引用在文件顶部
- [ ] 文件名 PascalCase，与 `Utils` 键名、模块表名一致
- [ ] 依赖通过 `UtilsSystem` 获取，子模块在顶部 `require`
- [ ] 私有函数未导出；内部数据未直接暴露
- [ ] 初始化使用 `Init()`，由 Manager 调用，业务模块间不互调 `Init`
- [ ] System / ToolSystem / 复杂模块 / Manager 有完整文件头（`Module`、`Description`、`Author`、`Created`、`Last Modified` 五项必填）；**P0**：新建或本次改写文件头时 `Author` 必须等于 `git config user.name`，禁止工具/助手名（见 §2.1.0）；**使用说明应尽量详细**（功能、模块关系、加载方式、典型示例等，见 §2.1.1）；**所有私有函数**有用途说明（有参/返回值则完整 `@param` / `@return`，格式 `名称 类型 - 说明`）
- [ ] 公共 API 每个 `@param` / `@return` 含类型与 `-` 后语义说明；`any`/`table` 已补充字段或取值说明（§2.3.1）
- [ ] 行内注释解释「为什么」，无复述代码、无大块注释掉的废弃逻辑
- [ ] 翻译键参数注明 `LanguageCfg` 键名；玩家可见文案见 [文本本地化开发规范](./文本本地化开发规范.md)
