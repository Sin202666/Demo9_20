# B3 三项拆层方案

对照 2026-08-31 复审：`NPCCosmeticHit`、`PlayerSkillClientManager`、`PlayerSkillManager` 维持不通过（架构 P0）。  
本方案只拆层与收口写口，**不改命中/伤害/装备权威**，**不新开 Remote**，**不新存档字段**。

> 创建：2026-08-31 · 作者：林奥宇  
> 状态：已按方案落地（2026-08-31）；待规范性复审改 B3 三项结论  
> Last Modified: 2026-08-31  
> 对照：SkillBuffUtil 拆写口（服 System + 客 stub、Utils 按端分流、Init 不互调 CombatWorld）

## 0. 目标与非目标

### 目标

| 项 | 现状 | 目标 |
|----|------|------|
| NPCCosmeticHit | AllSide `IsServer` 混写 Nearby 下行 + 客播轨 | 服写口在 `ServerSideCode/System`；客只播轨；无 `IsServer` 业务分支 |
| PlayerSkill* Manager | 跨槽裁决 / 旁观工厂 / 释放校验写在 Manager | 领域逻辑进 System；Manager 只启动、绑 Remote/输入、转发 |
| 模块表名 | `init.luau` 为 `local module = {}` | `NPCCosmeticHit` 与文件名 / Utils 键一致 |

### 非目标（本切片禁止顺手做）

- 不拆 `SkillHitPresentation` 的 `IsServer`（兄弟债，有条件通过，另开）
- 不改 `SystemSkill` 装备权威（Init/Equip/Unequip/存档槽）
- 不把 `GroupSkill` / `BaseSkill` 迁出 `ClientSideCode/SystemSkill`，不把它们登记进 Utils
- 不新 Remote、不改 NetMsg 字符串、不改 payload 字段语义
- 不改伤害、Hitbox、掉落、任务结算
- 不把 cosmetic 下行并进 `SystemEnemy.Hit` 函数体（调用关系保持 `Hit` → `NPCCosmeticHit.tryPlayLogical`）
- 不新开位移写口；击退/橡胶仍只经 `CharacterMotion` / `SystemCharacterMotion`

|------|-------------|--------|

| 旁观技能 | 仅表现 `BaseSkillClient`；不结算 | 从客 Manager 挪到客 System |
| 角色击退 / 橡胶 | 客 `CharacterMotion.Compose`；服 `SystemCharacterMotion.Fire*` | Manager 或客 System **只转发**，不 `PivotTo` / 不写 WalkSpeed |

**§1.7：** 禁止新脚本写 `CFrame` / `WalkSpeed` / `Store.cframe`。

## 2. 方案 A：NPCCosmeticHit（对照 SkillBuffUtil）

### 2.1 分层

```text
服  SystemEnemy.Hit
      → Utils.NPCCosmeticHit.tryPlayLogical   -- ServerSideCode/System/NPCCosmeticHit.luau
           → 读 enemyConf.animHitName、写 rec CD、Nearby FireClient(NPC_COSMETIC_HIT)

客  EnemyManager  Register NPC_COSMETIC_HIT
      → Utils.NPCCosmeticHit.handleIncoming   -- ToolSystem/NPCCosmeticHit（无 IsServer）
           → NPCCosmeticHitPlay.playFromPayload
```

Utils 分流（与 SkillBuffUtil / SystemEnemy 相同）：

```lua
NPCCosmeticHit = function()
    if IsServer and ServerSystemPath then
        local serverMod = ServerSystemPath:FindFirstChild("NPCCosmeticHit")
        if serverMod and serverMod:IsA("ModuleScript") then
            return serverMod
        end
    end
    -- 客户端：现 ToolSystem 目录模块
    ...
end
```

### 2.2 文件

| 路径 | 动作 |
|------|------|
| `ServerStorage/ServerSideCode/System/NPCCosmeticHit.luau` | **新建**：`tryPlayLogical`；`handleIncoming` 为 no-op；表名 `NPCCosmeticHit`；五项头 Author=林奥宇 |
| `ToolSystem/NPCCosmeticHit/init.luau` | **改写**：删除 `RunService:IsServer()`；只保留 `handleIncoming`；`tryPlayLogical` 为 no-op（防误调）；表名 `NPCCosmeticHit` |
| `NPCCosmeticHitClient.luau` | **删除**，转发并进 `init.handleIncoming`（6 行有效代码，无独立职责） |
| `NPCCosmeticHitPlay.luau` | **基本不动**（已是客播轨） |
| `UtilsSystem.luau` | 上表分流；键名仍 `NPCCosmeticHit` |
| `SystemEnemy.luau` / `EnemyManager` | **调用方不改**（仍 `Utils.NPCCosmeticHit.*`） |

### 2.3 约束

- 服模块禁止 `IsServer` / `RunService:IsServer()`。
- 不下沉到 `SystemEnemy` 内部：SystemEnemy 已通过复审，且职责是 Hit/Despawn，不是表现广播。
- Nearby 半径 / fade / CD 保持现常量；不抽共享库（避免碰 SkillHitPresentation）。
- 无 Init；不注册 CombatWorld；不绑 Remote（FireClient 经已缓存 `NetWork`）。

## 3. 方案 B：玩家技能运行时 → SystemPlayerSkill

### 3.1 为什么不并进 SystemSkill

现 `SystemSkill` 只做 **装备权威**（存档槽、默认技能、`BindGroupSkill` 点火）。释放裁决、槽位运行时表、旁观工厂是另一领域。并进去会破坏单一职责，并重开已通过审查的装备模块。

命名：`SystemPlayerSkill`（与两份 Manager 对应）。Utils 键同名。

- **服务端**：`ServerStorage/ServerSideCode/System/SystemPlayerSkill.luau`（必要时目录 + init；预计 <300 有效行则单文件）
- **客户端**：`ReplicatedStorage/ClientSideCode/SystemModule/SystemPlayerSkill.luau`
- **不要**登记进 `UtilsSystem` 的 ToolSystem `SystemModules` 表（否则会抢在 Server/Client 动态发现之前，加载到错误层）
- 服 `__index`：ServerStorage 动态发现；客 `__index`：SystemModule 动态发现。两端 `Utils.SystemPlayerSkill` 自然分流。

### 3.2 职责切分

#### 服务端 SystemPlayerSkill

从 `PlayerSkillManager` 迁入：

- 槽表 `Player → slotIndex → GroupSkillServer`
- `Bind` / `Unbind`（现 Bindable 回调体）
- `OnRelease`：存活、坐骑拒冲刺、飞行拒释、跨槽优先级、蓄力松键、`requestRelease` / `onInputRequest`
- `OnClientStop`：只打断该 player 自己的施法
- `OnPlayerDied` / `CharacterAdded` 钩 Died、`OnPlayerRemoving` 清表 + `SkillReleaseCrossCheck.clearCharacter`
- `_rejectRelease`（日志 + `SkillNet.ReleaseGroupSkill:FireClient(false)` + `SystemCharacterMotion.FireRubberband`）

`Init()`（仅 Manager 调；**必须在 PlayerSkillManager 脚本加载时同步调用**，与现 `RegisterBindableEvent` 同时机，先于任何 `SystemSkill.Init(player)`，否则 Bindable 会丢）：

- 绑 `Players.PlayerAdded` / 已在场玩家 Died、`PlayerRemoving`；连接按玩家收进表，Removing 时 Disconnect
- `NetWork.RegisterBindableEvent(BIND/UNBIND)` —— Bindable 同端，允许在 System.Init；**禁止**在 System 里 `RegisterServerRemoteEvent`

**禁止：** `CombatWorld.Init()`（服侧已由 `UpdateManager` 调用；Init 互调违反 §3.5）。

#### 客户端 SystemPlayerSkill

从 `PlayerSkillClientManager` 迁入：

- `LocalPlayerSkill` / `OthersInstanceMap`
- `_bindSkillByID`、听「技能相关」Skill1/Skill2/Dash
- `OnSlotPressed`（跨槽预打断 + `onInputBegan` 预测）
- `OnReleaseAck` / `OnFixSkillTime` / `OnStopSkill` / `OnSynSkillEffect`（含旁观 `BaseSkillClient` 工厂与中途 `handleServerEvent`）
- **不**处理 `SYN_PLAYER_CFRAME`、**不**调用 `CharacterMotion`（击退/橡胶转发留在客 Manager，见 §7 条件 4）
- 其它玩家离开：清 `OthersInstanceMap[userId]`（复审 P1，本切片做掉）

`Init()`：CharacterAdded + 听技能 Folder。不调 `CombatWorld.Init()`。

#### Manager 残留（薄编排）

**PlayerSkillManager（服）**

1. 门控：`技能系统.启用 == false` 则 return  
2. `SystemPlayerSkill.Init()`  
3. **不再** `CombatWorld.Init()`（避免与 UpdateManager 重复；CombatWorld.Init 幂等，但启动权只留 UpdateManager）  
4. `NetWork.RegisterServerRemoteEvent(RELEASE_GROUP_SKILL / CLIENT_STOP_SKILL)` → 转发 `SystemPlayerSkill.OnRelease` / `OnClientStop`  
5. `PlayerAimSync.initServer()` 仍由本 Manager 调（启动编排，不进 SystemPlayerSkill）

**PlayerSkillClientManager（客）**

1. 门控同上  
2. `CombatWorld.Init()`（客侧目前仅此处启动，保留）  
3. `SystemPlayerSkill.Init()`  
4. `SystemInput.SetBinding` + `OnAction` → `SystemPlayerSkill.OnSlotPressed`（输入编排留 Manager）  
5. `RegisterClientRemoteEvent` → 技能域转发 System 对应 On*；**`SYN_PLAYER_CFRAME` 只在本 Manager 内转到 `CharacterMotion.ApplyKnockback` / `RubberbandTo`**，不进 SystemPlayerSkill  
6. `PlayerAimSync.initClient()` 仍由本 Manager 调

### 3.3 长路径 require（约束，不升 P0）

`GroupSkillServer` / `GroupSkillClient` / `GetSkillData` / `BaseSkillClient` 仍在 `ReplicatedStorage/ClientSideCode/SystemSkill/`，未进 Utils。新 System **允许**与现 Manager 相同的顶部 `require(game.ReplicatedStorage.ClientSideCode.SystemSkill....)`，**本切片不把运行时登记进 Utils**（那是另一项迁层）。`Class` 同理。

### 3.4 共享常量

`DASH_SLOT_INDEX = 3` 两份 Manager + `SystemSkill` 重复。本切片在 `EnumMgr` 增加：

```lua
EnumMgr.SkillSlot = {
    Active1 = 1,
    Active2 = 2,
    Dash = 3,
    NormalAttack = 4,
    Block = 5,
    MaxRuntime = 5,
}
```

`SystemSkill` 与新 System / 两 Manager 改引用该枚举。`EnumMgr-Type.luau` 同步类型。不改槽位语义。

拒释 `reason`：本切片把 `"dead"` / `"mount_active"` / `"interruption_priority"` 收到 `EnumMgr`（UPPER_SNAKE 或现有错误码风格），避免魔法小写串。若为少改动，可先留字符串、标 P1；**推荐本切片一并改**，避免拆完立刻黄项超标。

### 3.5 行为微对齐（允许的唯一行为差）

现服 `GetIsFly` 为 true 时 **静默 return**，客预测层收不到 `accepted=false`。本切片 `OnRelease` 改为走 `_rejectRelease(player, slot, FLYING)`（或等价 reason）。不改飞行规则本身。

其余释放 / 跨槽 / 坐骑 / 松键 / 旁观路径 **行为对齐搬迁**（先搬后删 Manager 内实现）。

## 4. 通信与存档

| 通道 | 是否改协议 | 谁 Register |
|------|------------|-------------|
| `NPC_COSMETIC_HIT` | 否 | 仍 `EnemyManager`（客） |
| `RELEASE_GROUP_SKILL` / `CLIENT_STOP_SKILL` | 否 | 仍 `PlayerSkillManager`（服）→ System |
| `SYN_SKILL_EFFECT` / `STOP_SKILL` / `FIX_SKILL_TIME` | 否 | 仍客 Manager → System |
| `SYN_PLAYER_CFRAME` | 否 | 仍客 Manager → `CharacterMotion`（不进 System） |
| `BIND_GROUP_SKILL` / `UNBIND_GROUP_SKILL` Bindable | 否 | 改由 `SystemPlayerSkill.Init` Register |
| DataStore / SystemSave | 不碰 | — |

校验顺序（服 `OnRelease`）：玩家在线（NetWork 已注入 player）→ 槽表存在 → 存活 → 坐骑/飞行 → 跨槽 → `GroupSkillServer`。频率仍走 Skill 通道中间件，本切片不新做限频。

## 5. 实施顺序（通过 §1.8 且同意后）

1. EnumMgr `SkillSlot`（+ Type）  
2. NPCCosmeticHit 服模块 + Utils 分流 + 删 IsServer + 删 Client 转发文件  
3. 新建服 `SystemPlayerSkill`，Manager 改为转发；删 Manager 内裁决  
4. 新建客 `SystemPlayerSkill`，客 Manager 改为转发  
5. 飞行拒释补 FireClient；OthersInstanceMap 离场清理  
6. 规范性复审这五项：NPCCosmeticHit 服/客、SystemPlayerSkill 服/客、两 Manager  

每步保持可运行：先加 System 再切 Manager，避免空窗。

## 6. 验收

- 逻辑怪扣血：附近玩家仍播 `animHitName`；`hitstunDisabled` / CD 仍生效；不进 CombatWorld  
- `技能系统.启用 = false`：两 Manager 仍整段不跑  
- 槽 1/2、冲刺：预测 + 服否决清预测；跨槽优先级与现网一致  
- 旁观他人施法：中途事件仍到 BaseSkillClient  
- 死亡打断；坐骑中冲刺拒释 + 橡胶  
- 飞行中释放：客能收到失败（本切片对齐后）  
- 无 `IsServer` 业务分支出现在 NPCCosmeticHit / SystemPlayerSkill  
- 无第二套角色位姿写口

## 7. 开工约束（二次审评条件，必须遵守）

1. 无新 Remote / 无新存档字段 / 不改 payload 语义。  
2. System **不** `Connect`/`Register*Remote`；**不**调用 `CombatWorld.Init` 或其它模块 `Init`。  
3. 不把运行时并进 `SystemSkill`；不把 cosmetic 并进 `SystemEnemy` 函数体。  
4. **§1.7：** 客 `SYN_PLAYER_CFRAME` 击退/橡胶只在 `PlayerSkillClientManager` 转发 `CharacterMotion`；`SystemPlayerSkill`（客）禁止调 CharacterMotion / 写 CFrame / WalkSpeed。服拒释橡胶仍走 `SystemCharacterMotion.FireRubberband`（已有写口）。  
5. 本切片不拆 SkillHitPresentation。  
6. GroupSkill / Class 长路径 require 沿用，不扩 Utils。  
7. 新/改写文件头 `Author` = `git config user.name`（林奥宇），`Last Modified` = 开工日。  
8. 行为除「飞行拒释补通知客」外必须对齐搬迁。  
9. **时机：** `SystemPlayerSkill.Init()` 在服/客对应 Manager **脚本加载时同步调用**（与现顶层 Register 同序），保证先于 `SystemSkill.Init(player)` 与首包 Remote。  
10. 每玩家 `Died` / `CharacterAdded` 连接在 `PlayerRemoving` 时 Disconnect；客侧他人离场清 `OthersInstanceMap`。  
11. 同一改动更新 [`技能系统技术说明.md`](技能系统技术说明.md) §2 分层图：Manager 薄编排，运行时写 `SystemPlayerSkill`。
