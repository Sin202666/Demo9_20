# 文本本地化开发规范

玩家看到的文案必须走翻译键查表。完整流程见下文；新人先看精简版即可。

## 精简版

1. **入口**：`TranslationHelper.SetText` / `TranslateByKey`；数字、玩家名用 `SetRawText`。
2. **Key 只能是**：调用处的字符串字面量，或配置表 `Zh*` 字段（`ZhName`、`ZhDes` 等）。禁止 `cfg.Des`、自建 `KEYS[x]`、先赋变量再传入（上线前插件扫调用处参数，间接索引会漏）。
3. **加 Key 必须同步入表**：同一改动写入 `config/Localization/LocalizationTable.xlsx`。策划未译的文案格加 `/e`（Key 不加）；策划搜 `/e` 定稿后删掉。禁止只改代码。
4. **禁止手改** `Language.luau`（Excel 用 UGit 提交后钩子生成；不要用 Cursor 面板提交）。
5. 可变数字用 `{1}`，不要用 `addText`。静态 UI：标签 `本地化`，`Name` = Key。

---

## 1. 一句话流程

```
程序加 SetText / TranslateByKey
        │  同一改动写入 Excel（未定稿文案加 /e）
        ▼
config/Localization/LocalizationTable.xlsx
        │  提交 Excel，或先跑 scripts/ugit/3-本地打表测试.bat
        ▼
Language.luau（自动生成，禁止手改）
        │
        ▼
TranslationHelper.SetText / TranslateByKey
        │
        ▼
玩家 LocaleId 变化时，TranslationManager 刷新已绑定的 UI
```

---

## 2. 谁改什么

| 角色 | 做 | 不要做 |
|------|----|--------|
| 程序 | 加本地化时 **同步** 在 Excel 新增 Key；中英都填。策划未译的格子文案加 **`/e` 前缀** | 只改代码不入表；手改 `Language.luau`；在代码里写死展示文案 |
| 策划 / 文案 | 在 Excel 里搜 `/e`，写成正式中英文并 **去掉 `/e`** | 手改 `Language.luau` |
| Agent / 工具 | 实现功能时同样入 Excel（草稿 `/e`）；或给出完整行由人写入 | 直接编辑 `Language.luau`、`ConfigInstance.luau` |

`Language.luau` 与 `ConfigInstance.luau` 都是打表产物。需要新配置字段时，改 `config/*.xlsx`，不要改 luau 表。

## 4. Excel 怎么填

文件：`config/Localization/LocalizationTable.xlsx`（当前仅这一张）。

表头约定（与 `config/*.xlsx` 相同，前 3 行）：

| 行 | 内容 |
|----|------|
| 1 | 中文说明（打表跳过） |
| 2 | 字段名。必须有一列叫 **`Key`**，语言列名必须是 locale，如 `zh-cn`、`en-us` |
| 3 | 类型（文案列一般为 `string`） |
| 4+ | 数据。**Key 不能空、不能重复** |

示例（策划已定稿，无 `/e`）：

| Key | zh-cn | en-us |
|-----|-------|-------|
| 确认 | 确认 | Confirm |
| 库存为 | 库存：{1} | Stock: {1} |
| 赠送礼物确认 | 你确认赠送{1}给{2}吗 | Do you confirm gifting {1} to {2}? |

程序刚入库、策划未译（文案格加 `/e`，**Key 本身不加**）：

| Key | zh-cn | en-us |
|-----|-------|-------|
| 活动已结束 | 活动已结束 | /e活动已结束 |
| 光暗法杖描述 | /e光暗法杖描述 | /eLight-Dark Wand description |

`/e` 是给策划筛未译文案用的临时标记，会出现在游戏里，定稿后必须删掉。中文能先写正式句也可以先不打 `/e`，英文未译则 `en-us` 写 `/e` + Key 或草稿。

占位符写成 `{1}`、`{2}`（数字下标）。需要套另一条翻译时，代码侧传 `{ { "另一条Key" } }`，表内仍写 `{1}`。

当前正式语言：**zh-cn、en-us**。`zh-tw` 运行时回退到 `zh-cn`。缺当前语言时再回退 **en-us**。

## 5. 打表怎么跑

首次：双击 `scripts/ugit/1-安装或更新打表钩子.bat`（缺 Python 再跑 `2-安装Python环境.bat`）。

之后二选一：

1. **正常提交（程序、策划都一样）**：用 **UGit** 客户端或终端 `git commit`。Cursor / VS Code 源码管理面板有 Bug（3.15.6 起跳过 git 钩子），面板提交不会打表。工作区只要有 `config/**/*.xlsx` 变化（含未暂存、未跟踪），pre-commit 就会弹窗，不能静默打表或静默跳过。pull 后若提示钩子过期，点一键更新或跑 `1-安装或更新打表钩子.bat`。
   - **打表并提交**：校验通过后生成并暂存 `Language.luau` / `ConfigInstance.luau`；提交说明前缀 `【已打表】`
   - **不打表并提交**：对工作区全部配置表做打表校验（含本次不提交的区外表），通过才允许提交；不改 `src` 里的 luau，也不把 luau 产物加入本次提交（即使已勾选也不会加入区外表）；提交说明前缀 `【未打表】`
   - 可勾选（默认关）：把暂存区外的配置变化也 `git add`，再一起打表上传
   - 关闭窗口：取消本次提交
   表有错会弹失败窗并中止提交。两种提交都按工作区全量校验。未勾选不会把区外表加入提交。若已用 `3-本地打表测试.bat` 生成过 luau，也可以再在面板提交。
2. **先本地看效果**：双击 `scripts/ugit/3-本地打表测试.bat`，更新 src，不提交。

手工命令（一般不必）：

```powershell
powershell -File scripts/ugit/BuildConfig.ps1 -Mode Framework
```

校验失败（空 Key、重复 Key、缺语言列等）会中止提交。`config/.build/` 仅本机产物，不入库。

## 6. 程序怎么用

统一入口：

```lua
local Utils = require(game.ReplicatedFirst.AllSideCode.UtilsSystem)
local TranslationHelper = Utils.TranslationHelper
```

### 6.1 选哪个 API

| API | 用途 |
|-----|------|
| `SetText(ins, key, args?, addText?)` | **默认。** 给 `TextLabel` / `TextBox`（写 PlaceholderText）/ `ProximityPrompt`（写 ActionText）设文案，并打上可刷新绑定 |
| `TranslateByKey(key, args?)` | 只要字符串（Tips、拼接、搜索匹配等），不绑 UI |
| `SetRawText` / `SetText_UnTrans` | **纯数字、玩家名、已拼好的展示串** 等不参与查表、切语言也不刷新 |
| `SetLabel(ins)` | 用实例 `Name` 当 Key，等价 `SetText(ins, ins.Name)` |
| `CheckTranslateByKey(key)` | 键是否已在表中；缺键界面会显示 `未本地化-{Key}` |

`args` 为占位表。切语言后要还能对上，**必须用数字下标** `{ "库存为", { remain } }`，对应文案里的 `{1}`。

### 6.2 示例

```lua
-- 静态句
TranslationHelper.SetText(title, "确认")

-- 带数字 / 动态值
TranslationHelper.SetText(stockLabel, "库存为", { MathMgr.getNumStr(remain) })

-- 嵌套：外层句里的 {1} 再去翻物品名 Key（嵌套也必须是 Zh 前缀字段或字面量）
TranslationHelper.TranslateByKey("你已获得药水", { { itemCfg.ZhName } })

-- 配置表：只有 Zh 前缀字段能当 Key
TranslationHelper.SetText(nameLabel, itemCfg.ZhName)
TranslationHelper.SetText(desLabel, itemCfg.ZhDes)

-- 数字、玩家名：不走表
TranslationHelper.SetRawText(countLabel, "x" .. tostring(n))
TranslationHelper.SetText_UnTrans(nameLabel, player.DisplayName)

-- ❌ 禁止：非 Zh 前缀的配置字段当 Key（插件扫不到真实键，上线会漏）
-- TranslationHelper.SetText(desLabel, itemCfg.Des)
-- TranslationHelper.SetText(jumpLabel, cfg.JumpName)

-- ❌ 禁止：自己另建表存 Key，再拿索引传入（插件扫的是调用处参数，看不到表里的字面量）
-- local TAB_TITLE_KEY = { Shop = "活动商店", Task = "活动任务" }
-- TranslationHelper.SetText(title, TAB_TITLE_KEY[tab])
-- local KEYS = { Confirm = "确认", Cancel = "取消" }
-- TranslationHelper.SetText(btnLabel, KEYS.Confirm)
```

写在调用处：

```lua
-- ✅ 分支里直接写字面量
if tab == "Shop" then
	TranslationHelper.SetText(title, "活动商店")
else
	TranslationHelper.SetText(title, "活动任务")
end
```

### 6.2.1 Key 只能是字面量或配置表 `Zh*` 字段

传给 `SetText` / `TranslateByKey` / `CheckTranslateByKey`（含占位里的嵌套键）的 Key，**只允许**：

| 允许 | 示例 |
|------|------|
| 代码中的字符串字面量 | `SetText(title, "确认")` |
| 配置表带 **`Zh` 前缀**的字段 | `cfg.ZhName`、`cfg.ZhDes`、`cfg.ZhTalk`、`cfg.ZhEffectDes` |

**禁止：**

- `cfg.Des`、`cfg.JumpName`、`cfg.name`、`cfg.Note` 等任何非 `Zh` 前缀的配置索引
- 先赋给局部变量再传入（`local key = "确认"; SetText(ins, key)`）
- **自己另创表/常量映射存 Key，再 `KEYS.xxx` / `KEY_MAP[id]` 传入**——即便表里是字面量也不行

配置里若某列是给玩家看的文案，列名必须带 `Zh`（如描述用 `ZhDes` 而不是 `Des`），值仍是 Language Key，不是最终展示字。

**为什么：** 上线前会用插件扫项目里所有代码文本，找出还没进本地化表的 Key。字面量必须出现在本地化方法的参数位置才能被抽到；`Zh*` 是约定好的键来源，能和配置表对上。自建索引表、其它配置字段在调用处都看不到真实 Key，缺键会漏检。

### 6.3 两种 CollectionService 标签

| 标签 | 谁打 | 行为 |
|------|------|------|
| `本地化` | Studio 打在静态 UI 上 | 启动时用 **实例 Name = Key** 调 `SetText` |
| `代码本地化` | `SetText` 自动打 | 切语言时按 Attribute `_key` / `_arg*` 重翻 |

ProximityPrompt 的 Action 文案必须用 `SetText` 写入的 `_key`，**不要拿已经翻译好的 ActionText 再当 Key**（切语言会翻错）。

## 7. Studio 静态 UI

固定按钮、标题、提示条：

1. 在 Excel 增加 Key（建议 Key = 控件 `Name`，便于对照）。
2. 给 `TextLabel` / `TextBox` / `ProximityPrompt` 打标签 **`本地化`**。
3. 把实例 `Name` 设成该 Key。
4. **不要**在 Studio 里把 `Text` 当成最终多语言结果长期维护。

运行时才填的格子（列表克隆、倒计时、堆叠 `xN`）不要依赖模板上残留的 `代码本地化`：克隆会触发 `InstanceAdded` 再 `SetText`，把后缀冲掉。需要拼接时：去掉该标签 + `SetText_UnTrans`，或把可变部分放进 `{1}`。

---

## 8. 查表规则（运行时）

1. 当前 `LocaleId` 有文案 → 用它，并关掉实例 `AutoLocalize`。
2. `zh-tw` 没有单独条目 → 用 `zh-cn`。
3. 仍没有 → 用 `en-us`，并打开 `AutoLocalize`（交给 Roblox 自动本地化兜底）。
4. Key 根本不在表里 → 返回 **`未本地化-{Key}`**（联调时按这个搜缺键）。

默认语言常量是 `en-us`。

---

## 9. 必须遵守

1. **展示文案只来自 Key**，代码里出现的中文应是 Key 本身（或日志），不是给玩家看的句子。
2. **禁止手改** `Language.luau` / `ConfigInstance.luau`。
3. **传给本地化 API 的 Key：只能是字符串字面量，或配置表带 `Zh` 前缀的字段**（`ZhName` / `ZhDes` 等）。禁止 `cfg.Des`、`cfg.JumpName`，也禁止自建 `KEYS` / `TAB_TITLE_KEY[tab]` 再传入。上线前插件靠扫调用处参数找未完成本地化的 Key，间接索引会漏检。
4. **程序加本地化必须同步入表**：同一改动在 `LocalizationTable.xlsx` 加上 Key，中英都填。策划未译的格子用 **`/e` 前缀**（如 `/e活动已结束`），供策划搜索替换；禁止只写代码、等别人补表（界面会出现 `未本地化-`，插件筛查也会漏）。定稿后去掉 `/e`。
5. 可变数字、时间、数量放进 `{1}`，**不要**用 `SetText` 的第四参 `addText` 拼「库存 3」这类内容——切语言时 `addText` 不会被带上。
6. `SetRawText` / `SetText_UnTrans` 只用于确定不随语言变的内容。
7. 注释里若参数是翻译键，写明「`LanguageCfg` 键名，非展示文案」。
8. 百分号写在 Excel 文案里即可（如 `50%`）；查表侧已转义，不必在 Key 里避开 `%`。
