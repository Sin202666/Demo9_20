# 上线前审查标准

封板前对全仓做一次 **性能 / 数据安全 / 本地化 / 玩法逻辑** 静态审查，产出报告。  
审查技能：`.cursor/skills/pre-launch-review/`。触发语：**做上线前审查**。

> 创建：2026-08-31 · 作者：林奥宇 · Last Modified: 2026-08-31  
> 与 [模块规范性审查](模块规范性审查名单.md) 无关：本标准不审注释、文件头、Utils 缓存、函数是否超 80 行。  
> 依据：[代码结构和设计开发规范](代码结构和设计开发规范.md) §1.6 / §1.7 / §4 / §5 / §8；[文本本地化开发规范](文本本地化开发规范.md)。冲突时以本文件的上线结论规则为准，条款释义以结构 / 本地化文档为准。

---

## 0. 怎么用

1. 对 Agent 说：**做上线前审查**。默认 **只读出报告、不改代码**。
2. **一轮跑完全仓四域**（性能 → 数据安全 → 本地化 → 玩法逻辑），出一份总报告。
3. 要修再说「按上线报告修 P0」。
4. 无人工「需实测」签字时，结论 **最高只能「有条件通过」**，Agent 不得写「通过」。

---

## 1. 定位与边界

| | 模块规范性审查 | 上线前审查（本标准） |
|---|---|---|
| 目的 | 可维护、分层、注释 | 上线后别卡、别被刷、别露未译文案、别坏档 |
| 范围 | 单模块 / 一批 | 全仓，按四域扫 |
| 🔴 | 违反开发规范 | **上线阻断** |
| 最高结论（仅静态） | 通过 / 有条件通过 / 不通过 | **有条件通过** / 不通过 |

**Agent 能做：** 静态扫源码、Remote 注册、存档写口、配置交叉引用、翻译 Key 与 `/e`。

**Agent 不能做：** 测 FPS / 内存、进 Studio 点 UI、验证 rbxmx 上未入库的 `本地化` 标签。扫不到的标 **需实测 / 需人工**，不算误报，也不算该项通过。

**排除（不审实现风格，但仍审与结算的接线）：**

- 第三方：`SmartBone`；`GameAnalytics` 内部（只审项目如何接到 `ProcessReceipt`）
- 生成表：`Language.luau` / `ConfigInstance.luau` 的「手写风格」——但必须扫 `/e`、空 Key、重复 Key
- 数值手感、平衡（无策划基准时不报「太强太弱」）

## 2. 级别与结论

| 级别 | 含义 |
|---|---|
| 🔴 | 阻断发布：可刷、可坏档、可卡死服线程、玩家可见未译或 `/e`、正式服调试改档无门禁 |
| 🟡 | 可带缺陷发布但须登记：掉帧嫌疑、切语言丢参数、非经济 Remote 校验弱、失败语义不清 |
| 🟢 | 记录，不挡 |
| 需实测 / 需人工 | 不计入「通过」；计入有条件通过的条件 |

**结论：**

| 条件 | 结论 |
|---|---|
| 任一 🔴 | **不通过** |
| 无 🔴，且「需实测」清单已由负责人签字关闭 | **通过**（仅人工封板后；Agent 本轮不得给出） |
| 无 🔴，但需实测未签字，或 🟡 集中在同一子系统 | **有条件通过**（条件写回报告） |

不用「🟡 条数 ≤ N」当通过线，避免瞒报或乱标 🟢。

## 3. 扫描方法（四域一轮）

不要按模块再走规范性九类清单。按域搜，再对命中点向下追 2～3 层调用。

| 域 | 优先检索 |
|---|---|
| 性能 | `Heartbeat` / `RenderStepped` / `Stepped` / `while true` / `Instance.new` / `Clone` / `GetChildren` / `GetDescendants` / `FindFirstChild` / `WaitForChild` / `spawn(` / `wait(` |
| 数据安全 | `RegisterServerRemote` / `ChangeStat` / `DataStore` / `ProcessReceipt` / `DEBUG_` / `InvokeClient` / `FireAllClients` / `CfgFind` 后直接 `return` |
| 本地化 | `SetText` / `TranslateByKey` / `.Text =` / `ActionText` / `PlaceholderText` / `addText`；对照 `Language.luau` 与 `/e` |
| 玩法逻辑 | 所有会改货币 / 背包 / 任务标志 / 领取 / 购买 / 兑换 / 传送 / 技能结算 / 坐骑进入 的服务端路径 |

玩法域从 **写存档的函数往回追**，对每个写口问：谁调用、数据从哪来、失败回滚吗、能执行两次吗。

每条发现必须有：`文件:行号`、证据、玩家或经济后果、条款号、级别。禁止只写「不符合 §8.2」。不确定标需人工。

## 4. 性能（P）

静态只能找「会卡 / 会漏」的写法，不能代替对局压测。报告必须附 [§8 需实测清单](#8-需实测清单强制附录)。

**热路径：** `Heartbeat` / `RenderStepped` / `Stepped`、技能 tick、命中结算、足迹等每帧或每击触发的逻辑。  
**非热路径：** `Init`、玩家进入、打开一次的 UI。打开 UI 时的 `GetChildren` / `Instance.new` 为 🟡，不为 🔴。

### P1 热路径创建 / 销毁实例

- **查：** 热路径 `Instance.new`、`Clone`、无池的特效 / 伤害数字 / 足迹。
- **级别：** 热路径 🔴；低频 UI / 一次性 🟡。
- **勿误报：** `Init`、进玩家时建 UI、对象池首次扩容。
- **依据：** 结构 §8.2。

### P2 热路径遍历层级

- **查：** 热路径 `GetChildren` / `GetDescendants` / `FindFirstChild` / `WaitForChild`。
- **级别：** 热路径 🔴；打开 UI 时 🟡。
- **勿误报：** `ChildAdded` 维护的缓存、启动时扫一次。
- **依据：** 结构 §8.3。

### P3 轮询代替事件

- **查：** `while true do wait()`、弃用的 `spawn` / `wait`、空转 Heartbeat 只为隔几秒查一次。
- **级别：** `while true do wait()` 🔴；无必要的 Heartbeat 🟡。
- **勿误报：** 有退出条件（含 `player.Parent`）的节流 `task.wait` 循环。
- **依据：** 结构 §8.1。

### P4 连接 / 按玩家缓存不释放

- **查：** `Connect` 未入表；`PlayerAdded` 建状态而 `PlayerRemoving` / `destroy` 未清；按 `userId` 只增不删的表。
- **级别：** 按玩家建的连接未释放 🔴；模块级单例未说明 🟡。
- **勿误报：** `NetWork`、配置缓存等进程级单例。
- **依据：** 结构 §8.4。

### P5 热路径让出 / 远程 / 存档

- **查：** 热路径里 `task.wait`、`HttpService`、`DataStore`、`InvokeServer`。
- **级别：** 🔴。
- **勿误报：** 离开或定时的异步存档；把重活 `task.defer` 出本帧（仍须看是否每帧洪水）。

### P6 高频 Remote 通道与限频

- **查：** 技能 / 瞄准 / 移动是否独立 Channel；经济 msg 是否 `SetRateLimitConfig`。
- **级别：** 带结算的高频包无限频 🔴；纯表现同步走错通道 🟡。
- **勿误报：** 瞄准包可以高频，但服务端不得用它发奖（交叉 S1 / G6）。

### P7 同帧重复读会话 / 配置

- **查：** 同一函数多次 `GetPlrData`、循环内反复 `CfgFind` 同一 id。
- **级别：** 🟡。
- **勿误报：** 不同 player / 不同 id 的合法多次查询。

### P8 对象池该用未用

- **查：** 伤害数字、足迹、弹道、列表格子成对 `new` + `Destroy`，未走 `ObjectPoolUtil`。
- **级别：** 🟡。
- **勿误报：** 每分钟几次、寿命以秒计的物体。

### P9 资源常驻无释放

- **查：** 预加载是否只进不出；切图 / 离开是否调用已有释放 API（如 `ResMemoryManager`）。
- **级别：** 🟡，并标需实测。
- **实测：** 连续进出战斗 / 商店，内存是否台阶上涨。

## 5. 数据安全（S）

权威 + 存档 + 经济不可伪造。要看到具体 Remote 和发奖函数，不能只写「有分层」。

### S1 客户端权威结算

- **查：** 服务端用客机上报的击杀 / 完成 / 伤害 / 掉落 / 发奖数量直接 `ChangeStat` / `AddItem`。
- **级别：** 🔴（结构 §1.6）。
- **勿误报：** 客机预测 + 服最终结算；`NetworkOwnership` 位移但奖励仍服侧包络；纯 FX Remote。

### S2 客户端位置当领奖证据

- **查：** 宝箱、区域奖、到达类任务只信客机 `CFrame` / 上报坐标。
- **级别：** 🔴。
- **勿误报：** 服用自己的角色位置或逻辑怪 Store 位姿做距离判定。

### S3 绕过存档网关

- **查：** 业务 System / Manager / Gui 直接 `DataStoreService` / `SetAsync`；或不经 `ChangeStat` / `PlayerData.ChangePlrData` 改会话。
- **级别：** 🔴。
- **排除：** `SystemDataStore` 内部、GameAnalytics Store（结构 §5.2）。

### S4 Remote 缺校验链

- **查：** handler 是否按 会话已加载 → 类型 / 范围 / 配置存在 → 业务状态（持有、冷却、场景）再改数据。`NetWork` 中间件不代替业务校验。
- **级别：** 经济 / 进度 🔴；纯设置类缺类型检查 🟡。

### S5 价格 / 数量 / 物品 id 信客户端

- **查：** 购买、使用、合成、领取的 `count` / `price` / `itemId` 未回配置表或收据。
- **级别：** 🔴。

### S6 调试 / GM Remote

- **允许** 白名单或 Dev / Studio 门禁。**审查报告必须专节列出**每一个 `DEBUG_*` / GM 口：msgName、环境门禁、白名单来源、能改什么（背包 / 存档 / 邮件 / 重置）。
- **级别：** 正式服无环境门禁且无白名单即可改档 → 🔴；仅客户端藏 UI → 🔴；有白名单 / 门禁 → 不因此单项 🔴，但仍须在报告中点名，列入有条件通过的条件（确认名单与权限仍符合运营预期）。
- **勿漏：** `DEBUG_EMAIL` 一类「运营白名单、不受 Dev 开关限制」的口，必须写清：谁在名单里、能发什么、有无审计日志。

### S7 Robux 收据

- **查：** `ProcessReceipt` 是否按收据 `ProductId` + 购买历史幂等；失败是 `NotProcessedYet` 还是误 `PurchaseGranted`。
- **级别：** 非幂等或错绑发奖 🔴。
- **勿误报：** GameAnalytics 回调失败已隔离、主路径仍正确。

### S8 配置 / 缓存原表外泄可写

- **查：** `CfgFind` / `GameConfig.Get` / 查询 API `return` 活表且调用方可改字段。
- **级别：** 🔴。
- **依据：** 结构 §3.6。

### S9 服务端 InvokeClient

- **查：** `InvokeClient` / `OnClientInvoke`。
- **级别：** 🔴。
- **依据：** 结构 §4.4。

### S10 内部错误回传客户端

- **查：** RemoteFunction 回堆栈、内部 `err`、整份 `PlayerData`。
- **级别：** 带堆栈或存档内容 🔴；回稳定错误码（如 `BAG_FULL`）通过；回模糊内部串 🟡。

### S11 经济 Remote 无限频

- **查：** 领取 / 购买 / 兑换被 `HandlerOptions` 跳过限频，或未 `SetRateLimitConfig`。
- **级别：** 经济类 🔴；已配合理阈值 通过；瞄准包高频 勿误报。

### S12 存档不可序列化 / 迁移位置错误

- **查：** Player Store 写入 `Vector3` / Instance / 函数；`Init` / `PlayerAdded` 做版本迁移（应在 `FixData`）。
- **级别：** 🔴。
- **依据：** 结构 §5.1、§5.3。

### S13 多写口抢权威字段

- **查：** 位姿 / `WalkSpeed` / `Store.cframe` 绕过 `CharacterMotion` / `LogicEntityMotion` / `ActionArbiter`。
- **级别：** 🔴（结构 §1.7）。交叉 S2：抢写会使服侧距离校验与客机画面脱节。

### S14 广播他人隐私或整包会话

- **查：** `FireAllClients` 带完整 `PlayerData`、邮箱正文、CDK、收据。
- **级别：** 🔴。
- **勿误报：** `SystemRank` 镜像字段上榜。

## 6. 本地化（L）

开发期写法见 [文本本地化开发规范](文本本地化开发规范.md)。上线额外盯：`/e` 残留、运行时 `未本地化-`、Studio 静态 UI（Agent 扫不干净）。

### L1 玩家可见文案未走翻译入口

- **查：** Gui / Tips / ProximityPrompt 把句子直接赋给 `Text` / `ActionText` / `PlaceholderText`。
- **级别：** 🔴。
- **勿误报：** `Log`、注释、`error()`、正式服不加载的 Debug UI；数字 / 玩家名应走 `SetRawText`。

### L2 Key 不是字面量或 `Zh*`

- **查：** `cfg.Des`、`KEYS[tab]`、先赋变量再 `SetText`。
- **级别：** 🔴。
- **依据：** 本地化 §6.2.1、§9（插件扫调用处参数）。

### L3 Key 未入表或格子仍是 `/e`

- **查：** 代码字面量与配置 `Zh*` 是否出现在 `Language.luau`；`zh-cn` / `en-us` 是否以 `/e` 开头。
- **级别：** 🔴。
- **说明：** Agent 不改 Excel；只报缺行和 `/e` 行。

### L4 `addText` 拼接随语言会丢的内容

- **查：** `SetText` 第四参拼数量 / 时间 / 物品名。
- **级别：** 任务 / 支付文案 🔴；其它可见错 🟡。
- **正确：** `{1}` + `args` 数组。

### L5 `SetRawText` 用在整句上

- **查：** 「你获得了奖励」一类整句当 Raw。
- **级别：** 整句 🔴；`x12` / 纯数字倒计时 / `DisplayName` 通过。

### L6 占位与 args 对不齐

- **查：** 文案 `{1}{2}` 只传 1 个，或嵌套 Key 格式不对。
- **级别：** 🟡。

### L7 手改生成表

- **查：** 仅改 `Language.luau` / `ConfigInstance.luau`、同事 xlsx 的 git 形状；上线前是否重打表。
- **级别：** 确认手改 🔴；打表新鲜度未验证 → 需人工，并写入有条件通过条件。

### L8 静态 UI 未打 `本地化` 或 Name ≠ Key

- **查：** 仓库几乎没有 ScreenGui rbxmx，Agent **不得假装扫过 Studio**。
- **级别：** 需人工。报告必须列出须抽检的界面（登录、商店、背包、邮件、每日、设置、技能、死亡等）。未抽检则不能高于有条件通过。

### L9 克隆列表被 `代码本地化` 冲后缀

- **查：** 模板挂着 `代码本地化`，克隆后立刻 `SetText_UnTrans("x"..n)`。
- **级别：** 🟡。
- **依据：** 本地化 §7。

## 7. 玩法逻辑（G）

只报「状态机对不上」或「经济不守恒」的静态证据。不报手感、不报平衡。

### G1 发奖与扣费非原子

- **查：** 先发后扣中间 `return`；先扣后发失败不回滚。覆盖商店、每日、邮件、CDK、兑换码、Robux。
- **级别：** 🔴。

### G2 领取非幂等

- **查：** 「未领」判断与「标记已领」之间无先写后发 / 会话锁。优先 `CLAIM_DAILY_AWARD`、`EMAIL_CLAIM_AWARD`。
- **级别：** 🔴。
- **勿误报：** 仅 UI 防抖不够；服侧已先写标志再发奖。

### G3 接受非法数量

- **查：** `count <= 0`、非整数、超大数、`tonumber` 失败仍继续。
- **级别：** 🔴。

### G4 配置不存在仍结算

- **查：** `itemId` / `shopId` / `awardId` / `productId` 在配置为 nil 仍 `ChangeStat`。
- **级别：** 🔴。
- **勿误报：** 未知 id 整单忽略且无部分写入 + Log。

### G5 背包满 / 发奖失败被吞

- **满包与失败补偿策略随项目变化，审查只指出问题，不规定必须「回滚 / 进邮件 / 拒买」某一种。**
- **查：** 购买成功但入包失败；邮件标已领但物品没给；满包时销毁掉落且无失败回包。
- **级别：** 付费或邮件路径上奖励可消失 🔴；失败语义不清（玩家不知道发生了什么）但尚未证明丢进度 🟡。
- **报告写法：** 写清「哪一步成功、哪一步失败、玩家最终少了什么」，不要替项目选定策略。

### G6 技能 / 战斗信客户端命中清单

- **查：** `RELEASE_GROUP_SKILL` 等 payload 含目标列表 / 伤害 / 击杀且服照单记账；客户端 `HitResolver` 改血或发奖。
- **级别：** 🔴。
- **勿误报：** 仅预测受击特效；逻辑怪血量在 `EnemySim` 等权威侧结算。

### G7 冷却 / 消耗 / 锁定只在客户端

- **查：** 技能资源与 CD、坐骑条件、传送 CD 服务端不读会话即放行。
- **级别：** 🔴。
- **勿误报：** 预测动画 + 服拒绝回包后打断（无回包导致「看起来放了」→ 🟡 表现）。

### G8 传送 / 场景目标信客户端

- **查：** 目的地是否配置白名单，而不是客机任意 `CFrame`。交叉 S2。
- **级别：** 🔴。

### G9 坐骑 / 物品使用不校验所有权

- **查：** `MOUNT_REQ_ENTER` 的 `mountId` 是否在玩家数据中；使用物品是否在包且数量足够（先扣后生效）。
- **级别：** 🔴。

### G10 进度可跳步 / 可重复完成

- **查：** 任务 / 每日只靠 Remote「我完成了」；完成标志可被客户端设置。已读类 Remote 若附带发奖则须幂等。
- **级别：** 🔴。

### G11 状态机缺口

- **查：** 死亡后仍能放技能 / 购物；锁无解锁；坐骑中传送未清坐骑；打断技能清错 CD。
- **级别：** 能同时行动且能结算 🔴；仅表现卡死 🟡。

### G12 测试闸 / 无限资源进正式包

- **查：** 刷怪测试、Debug 改背包、未关的作弊开关是否在正式服仍加载。规范性审查可「跳过」测试闸，**本标准不能跳过**。
- **级别：** 正式服可加载并改档 / 刷资源 🔴。

### G13 排行 / leaderstats 可被客户端改

- **查：** 客户端写 `leaderstats` 或上报分数直接上榜。写榜只许 `SystemRank`。
- **级别：** 🔴。
