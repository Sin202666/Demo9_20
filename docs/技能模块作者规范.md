# 技能模块作者规范

> 面向技能内容作者：如何编写可加载、可校验、可量产的 GroupSkill / BaseSkill 模块。  
> 报错术语与 `BaseSkill/SkillModuleValidator.luau` **一一对应**。  
> 与仓库根 `docs/代码结构和设计开发规范.md` 分层：后者管架构分层；**本文管技能配置约定与禁旁路**。  
> 运行时架构 / 施法链路 / 与 3C 契约总览见 [`技能系统技术说明.md`](技能系统技术说明.md)。

## 1. 适用范围与模块地图

内容根目录：`src/ReplicatedStorage/ClientSideCode/SystemSkill/`（下表路径均相对该根）。

| 目录 | 职责 |
|------|------|
| `GroupSkillModule/<Name>.luau` | 组技能：CD、打断档、派生链、`Data`、同步半径、预测开关 |
| `SkillModule/<Name>.luau` | 基础技能：状态机、时间轴 Action、Hitbox/伤害配置、进出场回调 |
| `BaseSkill/SkillAction/*` | 可复用时间轴插件（Animation、LockMovement、DashStyleRoll…） |
| `SkillModule/_Templates/*` | 模板参考（如弹道追踪），勿直接当线上技能 |

**加载链路（简化）**

```
PlayerSkill*Manager 绑定
  → GroupSkillClient / GroupSkillServer.new
  → SkillModuleValidator.validateForRelease("GroupSkill", …)  -- 加载期挡非法配置
  → SkillDataSchema.normalizeSkillData(Data)
  → 施法时 BaseSkillClient / BaseSkillServer + SkillAction 时间轴
```

**框架样例（优先对照）**

| 样例 | 路径 | 特点 |
|------|------|------|
| NewRoll | `GroupSkillModule/NewRoll` + `SkillModule/NewRoll` | `predictPresentation=true`，`InterruptionPriority=70`，DashStyleRoll + LockMovement |
| SkillDemoCast | `GroupSkillModule/SkillDemoCast` + `SkillModule/SkillDemoCast` | 无预测；中档打断 50；Animation + LockMovement；与 NewRoll 共用 `RollForward` 测 TrackOwner |
| Meteor | `GroupSkillModule/Meteor` + `SkillModule/Meteor1` | **含 Hitbox** 主动样板；落地短窗「通用球」；`DamageRate={4.98}`；`PhysicsEffectName="中等力度受击物理效果"`（**地面击退**，非浮空）；LookAt + Animation；`predictPresentation=true` |
| SkillDemoProjectile | `GroupSkillModule/SkillDemoProjectile` + `SkillModule/SkillDemoProjectile` | **直线弹道**样板；`ProjectileLinearRuntime` + Path/Hit 同步；撞敌/撞障停飞 |

命名约定：`GroupSkillModule` 与 `SkillModule` 的 **ModuleScript.Name** 通常同名；`Data.skillName` **必须等于** 组技能 ModuleScript.Name。

## 2. GroupSkill 必填与推荐字段

### 2.1 Data

经 `SkillDataSchema.normalizeSkillData` 归一化。作者应显式填写：

| 字段 | 要求 |
|------|------|
| `skillName` | string，**等于** `GroupSkillModule` 脚本名 |
| `skillCooldown` | number，秒 |
| `skillElementType` | `EnumMgr.ElementTp.*` |
| `syncRadius` / `hitConfirmRadius` / `stopSyncRadius` / `damageTipRadius` | number；未填时由 Schema 默认/回落到 syncRadius |
| `predictPresentation` | 仅当需要客户端表现预测时设 `true`（还须全局总闸开启，见 §6） |
| `suppressions` | `{ [WARNING_CODE] = true \| "原因字符串" }`，豁免指定 warning（见 §4） |
| `clientObserverMaxDuration` / `clientObserverFxTailSeconds` | 可选；旁观表现兜底 |

### 2.2 Skill 派生表

```lua
module.Skill = {
  [1] = {
    baseSkillName = "YourSkill",  -- 对应 SkillModule 脚本名
    breakLastSkill = false,
    condition = { type = "literal", value = true },  -- 优先声明式，见 §9
  },
}
```

- `Skill` 缺失或非 table → 报错：`Skill 缺失` / `Skill 必须为 table`
- `Skill[i].baseSkillName` 非法 → `Skill[%d].baseSkillName 缺失或非法`
- `condition` 必须为 **function** 或 **声明式 table**，否则 → `Skill[%d].condition 必须为 function 或声明式 table`

### 2.3 InterruptionPriority

- 未配置时运行时视为中档 **50**
- **仅当** 新技能优先级 **严格大于** 对方 Phase1 中技能时，才可跨槽打断
- 冲刺类参考 NewRoll=`70`；普通主动技可用默认 50
- 若配置须为 number，否则 → `InterruptionPriority 必须为 number`

#### 跨槽打断后禁止派生（产品语义）

双端常量 `ENABLE_DERIVE_SUPPRESS_AFTER_CROSS_INTERRUPT`（`GroupSkillServer` / `GroupSkillClient`，须同值）当前为 **开启**。被更高优先级跨槽打断后：

| 项 | 定义 |
|----|------|
| 触发 | 仅当打断方 `InterruptionPriority` **严格大于** 被打断方 |
| 不停机 | 不强制 `Stop` 已开始的 BaseSkill 状态机 |
| 立刻做 | Over 各段 SkillAction、放权、清派生缓冲；客户端清一期预测 |
| 禁派生 | 本施法剩余 `Skill[]` 派生 / Chain 条件 / 按键派生全部关闭 |
| 新开释 | 同键再按若非派生，走正常 CD 新释（`shouldBypassCooldownForLocalPress` 为 false） |
| 复位 | 该组技能无 running runtime 后清除 `deriveSuppressedAfterCrossInterrupt` |
| 开关 | 双端常量须同值；当前 **开启** |

### 2.4 ChainWindows（多段/连招可选）

- `open` / `close` 须含 `state`；多段技能须显式 `baseSkillName` 或 `baseSkillIndex`
- 开闭不可倒挂（`open` 顺序须早于 `close`）；不可用终态作开/闭点  
  对应报错形如：`ChainWindows['%s'] open.state 顺序 ... 开闭倒挂`、`窗口不能以终态为起点/终点`

## 3. BaseSkill 状态机

### 3.1 必填骨架

| 字段 | 说明 |
|------|------|
| `States` | 状态表；缺失 → `States 缺失` |
| `InitialState` | 须存在于 States；缺失/非法 → `InitialState 缺失` / `InitialState '%s' 不存在于 States` |
| `Transitions` | `{ From, To, Event, Condition?, Priority? }`；From/To 须在 States |
| 终态 | 至少应有 `Finished`、`Interrupted`（`IsTerminal = true`） |

**状态图硬规则**（`SkillStateMachine.validateStateGraph`）：

| 报错 | 含义 |
|------|------|
| `终态 '%s' 存在出边，会导致终态复活…` | IsTerminal 禁止再转出 |
| `状态 '%s' 为死状态：无 Duration 超时且无出边…` | 非终态必须能离开 |
| `状态 '%s' 永远不可达：从 InitialState 无法到达` | 死配置 |
| `StateOrder 顺序倒挂：Transition A -> B…` | 有 StateOrder 时边须前进 |

非终态若 `Duration >= 0`，应有 `Event = StateTimeout` 的离开路径（框架 Timeout 语义）。

### 3.2 ControlOpenState / Phase1

- `ControlOpenState`：进入该状态时开放派生/放权窗口（如 NewRoll 的 `Recovery`）
- Phase1 完成前：跨槽打断、控制权仍视为占用中；完成后才进入 ChainOpen / Released（见 `SkillControlRuntime`）

### 3.3 Action 时间轴 vs StateActions

| 方式 | 用途 |
|------|------|
| `module.Action = { { action, startTime, overTime, ... }, ... }` | 相对技能时间轴的全局 Action |
| `module.StateActions[stateName] = { { action = "Animation", ... }, ... }` | 进入某状态时挂载；键须合法状态名，`action` 须为 `SkillAction` 下模块名 |

非法时常见报错：`StateActions['%s'] 不是合法状态名`、`未知 action '%s'`。

常用 Action：`Animation`、`LockMovement`、`DashStyleRoll`、`LookAt`（以 `BaseSkill/SkillAction` 目录为准）。

### 3.4 animationPlaySide（可选）

仅非玩家主体生效；取值 `"Client"` \| `"Server"`，非法 → `animationPlaySide 必须为 "Client" 或 "Server"…`。

### 3.5 Validator 错误术语速查（节选）

| 术语 | 出现场景 |
|------|----------|
| `Data.skillName 缺失` / `与模块名不一致` | 命名错误 |
| `States 缺失` / `必须为 table` | BaseSkill 范式 |
| `Transition From/To '%s' 不存在于 States` | 边引用错误 |
| `StateOrder 必须为 table` / `引用状态…不存在` | 弹道/窗口顺序表 |
| `ChainWindows['%s']…` | 连招窗口结构 |
| `hitboxConfig[%d].damageProfileId '%s' 不存在于 DamageProfiles` | 伤害配置断裂 |
| `ProjectileProfiles` 同类引用错误 | 弹道配置断裂 |
| `skillModule 必须为 table` | 加载失败 |

## 4. Warning 可治理

代码：`SkillModuleValidator.WARNING_CODES`。

| Code | 默认级别 | 含义 | 豁免 |
|------|----------|------|------|
| `TransitionFuncCondition` | warn | Transition 使用 function Condition，无法静态验证 | `Data.suppressions` 或 options |
| `SkillFuncCondition` | **block_production** | `Skill[].condition` 为 function | 须特批；推荐改为声明式 |
| `SkillLiteralTrueAlways` | **block_production** | 声明式 `literal=true`（单段无派生样例可豁免） | 见 SkillDemoCast |
| `WindowOrderRisk` | warn | 窗口顺序风险（预留/扩展） | 按需 |

**豁免写法（推荐带原因字符串）：**

```lua
module.Data = {
  skillName = "SkillDemoCast",
  -- …
  suppressions = {
    SkillLiteralTrueAlways = "原因：单段样例无派生，首段 literal=true",
  },
}
```

`validateForRelease` 在加载时走 **strict**：未豁免的 warning 也会失败。生产 `env="production"` 时，未豁免的 `block_production` 一律阻断。

## 5. SkillAction 与 3C 禁旁路

技能作者**只声明** Action / 配置；禁止旁路控制层写口。

| 需求 | 正确路径 | 禁止 |
|------|----------|------|
| 播技能轨 / Slot 层叠 | `SkillAction.Animation` → **AnimationLayer**（`animSlot`/`blendPolicy`）+ `SkillActionLock` | 业务手写多轨 Priority 抢腿且不占闸 |
| 冻 loco / 暂停基轨 / 朝向占用 | Animation / DashStyleRoll → `SkillActionLock(blendPolicy)` → **ActionArbiter** | 自写 `SkillActionLock` Attribute；绕过 Arbiter 冻腿 |
| 边跑边上身施法 | `animSlot="Upper"` + `blendPolicy="Overlay"` + **未键腿**资源 | 全身片 + Overlay（会钉死跑腿）；Idle 档盖 Land |
| 改 WalkSpeed | `LockMovement` → **CharacterMoveSpeedBind** Modifier | 直写 `Humanoid.WalkSpeed` |
| 禁跳 / 禁奔跑 / 禁视角写 / 禁交互 | `CharacterControl:PushLock` 或 `TransferControlOwner` | 私改 AutoRotate / 各脚本自绑交互键且不读 LockMask |
| 前冲 FOV 脉冲 | **`CameraImpulse.emit`**（AnimateFov 唯一 Helper 消费） | 平行 Helper「冲刺影响相机FOV」；业务直写 `CurrentCamera.FieldOfView` |
| 冲刺 / 翻滚位移 | **`DashStyleRoll` → `CharacterMotion` Drive**（SkillActionLock + ActionArbiter + Jump/Sprint + CameraImpulse；PreserveY；`MaxForceClip`；**LockMovement 寿命=tweenDuration**；服轻量包络） | 裸 `BodyVelocity` / 自写位移 Action；直写 `AssemblyLinearVelocity`；客户端裸改 `HRP.CFrame` 做权威位移；ToolSystem require SkillActionLock |
| 角色击退 | **`CharacterMotion.ApplyKnockback` / `AddImpulse`**（与 Drive 同一电机；HitResolver → `SystemCharacterMotion.FireKnockback` → 所有者客户端） | 角色 HRP 上 `BodyVelocity` / 旁路 ALV（可破坏物碎片除外） |
| 镜头接管 | 仅真正 External 驱动时设 `cameraOwner=External` | 技能占闸仅为冻腿时改 cameraOwner（SkillActionLock 保持 Default） |
| 技能逻辑 / Hitbox / 表现主循环 Tick | **`Utils.CombatWorld.register`**（存 handle 到 `runData.runEvent`，退出态 `Disconnect`） | `RunService.Heartbeat:Connect`（每施法一条会炸连接数）；`BaseSkillRuntimeHost.startClock` 仅框架用 |
| 逻辑怪 AI / 位移 Tick | **`EnemySim`**（`CombatWorld.Phase.EnemySim`）；经 `SystemEnemy.CreateLogicalEnemy` 装配 | 每怪 `Heartbeat`；`AiHost.connectHeartbeat`；在 SkillModule 里私建怪仿真时钟 |

纯表现跟随可用 `RenderStepped`（如尾迹贴点），**不得**在 Heartbeat/RenderStepped 里做伤害、Hitbox start/stop、权威位移。详见 [`战斗仿真ECS迁移方案.md`](战斗仿真ECS迁移方案.md)。

### 5.1 直线弹道（SkillDemoProjectile 约定）

| 需求 | 正确路径 | 禁止 |
|------|----------|------|
| 弹道位移 / Hitbox 跟随 | `_Templates/Projectile/ProjectileLinearRuntime.start/stop`（内部 `CombatWorld.Phase.Hitbox`） | 私建 Heartbeat；在 Tick 内写 DataStore / 绑 Remote |
| 服务端撞敌 | `onProjectileHitServer` → `HitResolver.applyHit`（含逻辑怪 **number id**）→ `ImpactResolver.resolveImpact` → `fireProjectileHitConfirmed` | 仅客户端判伤；假定 `GetPartsInPart` 能扫到 LocalMonster |
| 服务端撞障 | `Server_UpdateProjectileObstacleCheck` + `FriendlyRayUtil.raycastProjectileObstacle` | 把敌方 Humanoid / LocalMonster 当障碍 |
| 路径/命中同步 | `fireProjectilePathConfirmed` / `fireProjectileHitConfirmed`；客户端 `onServerEvent` | 假定 Manager 会自动播表现（须实现 `onServerEvent`） |
| 自瞄追踪 | 后置；`ProjectileObjectTracking` 仍占位 | 本轮勿实现追踪弹 |

样板：`SkillModule/SkillDemoProjectile`。模板勿当线上技能直接挂槽（可复制后改名 + 配表 ScriptName）。

### 5.2 逻辑怪命中（作者须知）

| 需求 | 正确路径 | 禁止 |
|------|----------|------|
| 打逻辑怪 | 服 `Hitbox.check` 自动补 `collectLogicalOverlapHits`；`applyHit` 遇 number 走 `applyLogicalEnemyHit` | 客 `GetPartsInPart` 扫 LocalMonster；服隐形 Part 当伤害体积 |

### 5.3 逻辑怪受击运动（`PhysicsEffectName`）

Hit 后服端分流（作者只配 hitbox 字段，禁止自建怪时钟）：

| 需求 | 正确路径 | 禁止 |
|------|----------|------|
| 地面击退 | `hitboxConfig[].PhysicsEffectName` 取 `LogicalDisplaceProfile` 键（如 `"中等力度受击物理效果"`）→ `LogicalDisplace`（EnemySim） | 在 SkillModule 里改 `Store.cframe`；给怪加 BodyVelocity |

| 同名互斥 | 一档名只出现在 Displace **或** Airborne 表；Hit 先查 Airborne | 同一 `PhysicsEffectName` 两边都配 |

**TrackOwner**：跨槽若共用同一动画名（如 Demo 与 NewRoll 的 `RollForward`），须理解 `SkillAnimationTrackOwner`——打断方应能完整重播，旧 Action 不得误停新轨。量产技能尽量避免无必要的同轨复用。

## 6. 表现预测

- 全局总闸：`SkillDataSchema` 内 `GLOBAL_PREDICT_PRESENTATION_ENABLED`
- 单技能：`Data.predictPresentation == true` 且总闸开启后才会真正预测
- 语义：本地无 Hitbox 模拟至 `ControlOpenState` / Phase1 后 hold；服务端确认后 **soft-merge**（动画/物理/ActionLock adopt，禁止二次起冲与 FOV 二次放大）
- 拒释（CD/死亡等）：须清预测物理与闸（参考 NewRoll 组模块头注释验收清单）
- 旁观：不预测，等 `BaseSkillStarted`

冲刺 FOV：`CameraImpulse.emit(..., adoptIfActive=true)` 在 soft-merge 时不重开脉冲。

## 7. 命中与配置引用

- `hitboxConfig[i].damageProfileId` 必须存在于 `DamageProfiles`
- 弹道相关 profileId 必须存在于 `ProjectileProfiles`
- 即使客户端 Hitbox 默认关闭，配置仍须完整，供**服务端权威**结算管线使用
- 无伤害技能可 `hitboxConfig = {}`（如 SkillDemoCast）
- 含 Hitbox 主动样板对照 `SkillModule/Meteor1`：`hitboxConfig` + 服务端状态回调里 `Data.hitbox[i]:start/stop`（及落点 `PivotTo`）
- **逻辑怪**：无需技能侧额外配置；服 Player/Mirror Hitbox 与弹道自动补查 OBB（见 §5.2）。勿依赖客户端扫到 `workspace.LocalMonster`

施法输入：服务端会 `sanitizePlayerCastInput`（`releaseCF` 用角色 Pivot，`targetCF` 按距离钳制）。作者不要假设客户端落点可信。

## 9. 最小骨架示例

### GroupSkill（单段，无预测）

```lua
local module = {}
local Utils = require(game.ReplicatedFirst.AllSideCode.UtilsSystem)

module.InterruptionPriority = 50

module.Data = {
  skillName = "SkillDemoCast", -- 必须等于脚本名
  skillElementType = Utils.EnumMgr.ElementTp.None,
  skillCooldown = 1,
  syncRadius = 80,
  predictPresentation = false,
  suppressions = {
    SkillLiteralTrueAlways = "原因：单段样例无派生，首段 literal=true",
  },
}

module.Skill = {
  [1] = {
    baseSkillName = "SkillDemoCast",
    breakLastSkill = false,
    condition = { type = "literal", value = true },
  },
}

return module
```

### BaseSkill（状态机 + Action 摘录）

```lua
module.InitialState = "Startup"
module.ControlOpenState = "Recovery"

module.States = {
  Startup = { Duration = 0 },
  Active = { Duration = 0.45 },
  Recovery = { Duration = 0.35 },
  Finished = { Duration = 0, IsTerminal = true },
  Interrupted = { Duration = 0, IsTerminal = true },
}

-- Transitions：StateTimeout 推进；Interrupt / ForceFinish 进终态
-- Action：Animation + LockMovement(speedMultiplier=0)
```

完整字段见 `SkillModule/SkillDemoCast.luau`、`SkillModule/NewRoll/`（`init.luau`）。

### 声明式 condition

支持运算符 `all` / `any` / `not`，叶子类型 `chain_input` / `window` / `state_before` / `state_passed` / `literal`。详见 `GroupSkill/DeclarativeCondition.luau`。

```lua
condition = {
  all = {
    { type = "chain_input", index = 2, buffer = 0.25 },
    { type = "window", name = "Combo2" },
  },
}
```
