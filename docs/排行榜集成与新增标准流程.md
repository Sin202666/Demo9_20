# 排行榜集成与新增标准流程

> 面向业务接入与新增一榜：写分、写 ODS、workspace 镜像、客户端 SurfaceGui。  
> 分层总览见 [`代码结构和设计开发规范.md`](代码结构和设计开发规范.md)（ServerStateSync / 客户端只读）。  
> 配置权威：`src/ReplicatedFirst/AllSideCode/ToolBasic/RankConfig.luau`。  
> Last Modified: 2026-09-01

---

## 1. 模块地图与数据流

| 层级 | 模块 | 职责 | 禁止 |
|------|------|------|------|
| 共享配置 | `RankConfig` | 写榜键、Record 字段、展示格式、Board 映射 | 业务旁路硬编码中文键 |
| 服务端统计 | `SystemRecord` | 权威分数来源（`RecordAdd` / `RecordCover`） | 客户端改分上榜 |
| 服务端写榜 | `SystemRank` | Record → OrderedDataStore；拉页 → workspace 镜像 | 业务直接 `DataStoreService`；客户端写镜像 |
| 客户端展示 | `SystemRankManager` | 只读 workspace，绑 SurfaceGui | 写 Store / 写「前3名玩家」 |
| 薄启动 | `UpdateManager` / `RankManager` | 分别 `SystemRank.Init` / `SystemRankManager.Init` | Manager 内写业务分 |

```
业务 System（服务端）
  → SystemRecord.RecordAdd/Cover(player, RankConfig 字段, n)   -- 权威分
  → [可选] SystemRank.UploadPlayer(player)                    -- 尽快上榜
  → SystemRank 定时 UploadPlayerRankInfo / PlayerRemoving 冲榜
  → OrderedDataStore（编码分 MathMgr.getRankNum）
  → SystemRank.UpdateRank → workspace.排行榜缓存 / 前3名玩家
  → SystemRankManager 读缓存 → SurfaceGui 格子
```

**当前已登记榜：** `N_Time`（时长）、`N_Robux`（罗宝）、`N_Gold`（金币）。无战力榜。

## 2. 业务接入已有榜（只写分）

### 2.1 正确写法

```lua
local RankConfig = Utils.RankConfig
local SystemRecord = Utils.SystemRecord
local SystemRank = Utils.SystemRank

-- 字段键必须走 RankConfig，禁止抄中文串
SystemRecord.RecordAdd(player, RankConfig.RANK_DATA_FIELDS[RankConfig.RANK_GOLD_NAME], n)

-- 仅「需要尽快上榜」时调用（如付费成功）；金币/时长靠定时批量写榜即可
SystemRank.UploadPlayer(player)
```

也可用 `RankConfig.GetRecordField(RankConfig.RANK_ROBUX_NAME)` 缓存在模块顶部常量。

### 2.2 接入清单

| # | 动作 | 说明 |
|---|------|------|
| 1 | 确认目标榜在 `RANK_NAMES` | 未登记则先走 §3 新增 |
| 2 | 在**服务端**业务 System 累加/覆盖对应 Record 字段 | 权威只在服务端结算 |
| 3 | 决定是否 `UploadPlayer` | 低频高价值事件才立即写；热路径每笔不要调 |
| 4 | 不要调 `UploadPlayerRankInfo` | 批量写榜仅 `SystemRank` 定时任务 |

### 2.3 禁止

- 客户端上报分数直接上榜 / 写 `leaderstats` 当权威
- 业务直接 `SystemDataStore.SetOrdered` 或改 `MathMgr.getRankNum` 算法
- 业务定时轮询 `UploadPlayerRankInfo`
- 硬编码 `"总金币获得"` 等中文键（必须 `RANK_DATA_FIELDS[...]`）

## 3. 新增一榜清单

按顺序做完；缺任一步会出现「有分无板 / 有板无字 / 不上榜」。

### 3.1 RankConfig（必做）

文件：`ToolBasic/RankConfig.luau`（并同步 `Interface/RankConfig-Type.luau` 常量与 API 签名）。

1. 增加 `RANK_*_NAME` 常量（如 `N_Kill`）
2. 加入 `RANK_NAMES`
3. 在 `RANK_DEFS` 增加条目：

| 字段 | 含义 |
|------|------|
| `recordField` | `SystemRecord` 统计键（中文存档字段名） |
| `scoreFormat` | `"number"` 或 `"duration"` |
| `monotonic` | `true` = ODS 只升不降（读旧分失败则本轮不写） |
| `gradient` | UI 格子 BG 渐变类型名（可选） |
| `slotCount` | 展示格数，默认 `RANK_COUNTS`（≤100） |

4. 可选：`SCENE_BOARD_TO_RANK` 显式别名；Board 已按 `Rank_` + 写榜键命名时可省略（前缀规则会解析）

### 3.2 写分来源（必做）

- 选定**一个**服务端 System 对 `recordField` 做 `RecordAdd` / `RecordCover`
- 原始分 `<= 0` 不会上榜（与拉榜最低分过滤一致）
- 需要尽快上榜时在结算成功路径调 `SystemRank.UploadPlayer(player)`（参考 `SystemBuyRoblox` 罗宝）

### 3.3 本地化（必做）

写入 `config/Localization/LocalizationTable.xlsx`（zh-cn + en-us；未译加 `/e`）。**禁止**手改 `Language.luau`。

| Key | 用途 |
|-----|------|
| `排行榜标题-<名>` | 该榜 `RankTitle` 标题（新建一榜必加） |
| `排行榜-排名` / `排行榜-数量` / `排行榜-玩家` | 表头（已有则复用） |
| `排行榜时长` | 仅 `scoreFormat = duration` 时分数格子 |

### 3.4 客户端标题绑定（必做）

在 `RankBoardBind._bindRankTitleText` 增加 **字面量** `SetText` 分支（本地化禁止 `KEYS[x]` / 赋变量再传入）：

```lua
if rankName == RankConfig.RANK_XXX_NAME then
	TranslationHelper.SetText(rankTitle, "排行榜标题-xxx")
	return
end
```

### 3.5 场景 Board（必做）

路径：`workspace.场景/<世界>/功能/排行榜/<Board>`

```
Rank_<写榜键>/                          -- 例 Rank_N_Gold → 缓存键 N_Gold
  Board/SurfaceGui/Content/
    Main                                -- 榜单格子容器（Frame 或 ScrollingFrame）
    MyRank                              -- 自己名次槽
    排行榜-排名 / 排行榜-数量 / 排行榜-玩家
  title/SurfaceGui/RankTitle            -- 实例名；文案由 Bind 写入，勿用 Name 当 Key
```

格子模板 `RankTemp`（`ModelRes/排行榜` 或 `UI/排行榜`）子节点约定：

`Frame` / `Username` / `Rank` / `Number` / `Portrait` / `BG`

- 客户端只从 `ReplicatedStorage`（Shared）解析 RankTemp
- 若模板仅在 ServerStorage，`SystemRank.Init` 会克隆到 `RS.Assets.UI/排行榜`

### 3.6 按榜类型补齐

| 条件 | 额外动作 |
|------|----------|
| `scoreFormat = duration` | Refresh 已走 `TimeTransfer.GetRankDurationParts` + `SetText("排行榜时长")`；确认键存在 |
| `monotonic = true` | 接受「读旧分失败则本轮不上写」；业务侧勿指望降分立即反映 |
| 需场景装扮读前三 | 用 `SystemRank` / `SystemRankManager.GetTop3UserIds`；UI 榜面不读「前3名玩家」树 |

### 3.7 无需改动（已自动覆盖）

- `SystemRank.Init` / 定时写榜与拉榜：遍历 `RANK_NAMES`
- workspace 缓存文件夹：按榜名自动 `InsMgr.GetIns`
- `RankManager` / `UpdateManager` 启动链：一般不用为新榜改 Manager

## 4. 查询 API（只读）

两端同名；返回**新表**、分数为**解码后原始分**（workspace `Score` 存的是编码分）。

| API | 说明 |
|-----|------|
| `GetTop3UserIds(rankName)` | 最多 3 个 UserId |
| `GetCacheEntries(rankName)` | `{ userId, score }[]` |

客户端也可：`SystemRankManager.IsReady` / `OnBoardsReady` 等榜板绑完再读。

## 5. 硬约束（P0）

1. **写榜权威仅 `SystemRank`**；客户端 `SystemRankManager` 只读镜像、只写本地 SurfaceGui。
2. **分数权威在 `SystemRecord`**；业务不要绕过 Record 直接 SetOrdered。
3. **禁止修改 `MathMgr.getRankNum` / `backRankNum`**：现网 ODS 已按该算法编码，改算法会打乱排序。
4. **无 Remote 写榜**；无排行相关玩家存档新字段（Record 动态项除外）；排行本身不发奖。
5. 新榜涉及新 System / 新 Remote / 存档结构时，先走结构规范 **§1.8 二次审查门**，再实现。

## 6. 自测清单

- [ ] Studio：`UpdateManager` 在 `SystemRank.Init` 后会立刻 `UpdateRank`，workspace 出现该榜缓存槽
- [ ] 服务端把 Record 分加到 `> 0` 后，等待写榜周期或调 `UploadPlayer`，再 `UpdateRank`，缓存出现自己
- [ ] 客户端进厅：对应 `Rank_*` 板有标题、表头、格子；时长榜显示「天+小时」本地化
- [ ] `monotonic` 榜：人为降 Record 分后，ODS 不降（或读失败本轮不写）
- [ ] 原始分 `0` / 负分：不上榜
- [ ] 热挂载：运行中把 Board 放进 `功能/排行榜` 仍能绑板（不限大厅世界）
