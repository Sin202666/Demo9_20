# 逻辑怪位移与寻路开发计划

把逻辑怪从「直线 Seek + 贴墙停住」补到可商用的**地面移动层**：沿墙滑移、脚本命令接管、路点寻路。  
战斗闭环（怪打人）仍走总方案 **C1 Attacking**；本计划是其并行运动轨，**不**替换 `CombatWorld` / 不换 Matter·JECS。

> 总方案：[`战斗仿真ECS迁移方案.md`](战斗仿真ECS迁移方案.md) §4.3.2 / §4.5。  
> 审评结论：调度与受击运动可用；运动轨 **M0–M2 已手测封板**（原地面 3/10、寻路 1/10 缺口已补）。  
> 商业对标：UE AI MoveTo + NavMesh、Unity NavMeshAgent（路点跟随 + 卡住恢复）；Roblox 侧用引擎 `PathfindingService`，自研薄封装，不引入社区 SimplePath 库。

## 1. 背景与动机

### 1.1 现状

| 层 | 模块 | 行为 |
|----|------|------|
| 调度 | `CombatWorld` + `EnemySim` | 批处理；禁每怪 Heartbeat |
| 受击 | `LogicalAirborne` → `LogicalDisplace` | 覆盖 AI；商用切片够用 |
| 地面移动 | `LogicEntityMotion` | **M0 已落地**：切向滑移 + 卡住改向；**到达才 clearGoal** |
| AI | `RangerAi` | Idle / Wandering / Chasing 环带；M1 起只写 `_desiredPos` |
| 命令 | `LogicalMoveCommand` | M1：`Auto` / `ScriptGoal` / `ScriptDir` / `Pause` |
| 寻路 | `LogicalPathFollow` + `PathFindUtil` | **M2 已落地并手测**：PathfindingService 路点；无路径直线 + M0；迷宫 Chase 可绕到玩家 |

客户端 `LocalMonster` 的 Humanoid 处于 Physics，**不**驱动位移。玩家 `CharacterControl` / `CharacterMotion` **不**并入逻辑怪。

### 1.2 要解决的问题

1. **卡死：** 柱子、墙角、室内隔墙时直线撞墙即停，巡逻/追击失效。  
2. **无法脚本控怪：** 关卡、演出、技能强制走点没有命令层（只能改 Store 瞬移或偷偷写 `_logicalGoal`，会被 Ranger 覆盖）。  
3. **无寻路：** 看不到的目标仍直线追；NavMesh / 路点不存在。  
4. **意图与积分耦合：** AI 直接 `setGoal`，无法插入「目标点 → 下一路点 → 积分」。

### 1.3 成功标准（产品向）

- 开放空地行为与现网一致（巡逻、环带、击退/浮空不被破坏）。  
- 简单障碍（矮墙、柱）可沿墙滑过或卡住后改向，不再永久 Idle。  
- 关卡脚本可 `PauseMoveAi` / `SetMoveGoal` / `ResumeMoveAi`，期间 Ranger 不抢目标；受击锁仍优先。  
- 隔墙追击：有 NavMesh 时走路点；失败则回退直线（可配置），并有计算预算上限。  
- 全程无每怪 Heartbeat；`ComputeAsync` 只在 `task.spawn` 队列里跑。

| # | 议题 | 决议 |

| D1 | 是否换 ECS 库 | **否** |
| D2 | 移动是否走玩家电机 | **否**；只扩 `LogicEntityMotion` + 新模块 |
| D3 | 寻路实现 | **PathfindingService**（`CreatePath` + `ComputeAsync`）；禁止业务直接调服务 |
| D4 | Compute 线程 | **禁止**在 `EnemySim.step` 内 yield；`task.spawn` + 每帧配额（建议 2～4 次） |
| D5 | 无路径时 | **回退直线 Seek**（现行）；可选 `entity.pathRequired=true` 则停步等待重试 |
| D6 | 命令 vs AI | Script* / Pause **覆盖** Ranger；Airborne / Displace / moveLock **覆盖**命令 |
| D7 | 贴墙策略 | 切向滑移；连续 N 帧步长≈0 才视为卡住（改向或请求重寻路），**禁止**一撞墙就清目标 |
| D8 | 同步 | 仍 20Hz TRANSFORM；寻路不新 Remote |
| D9 | Agent 尺寸 | `AgentRadius` ← bbox 水平半宽；`AgentHeight` ← bbox.Y；`AgentCanJump=false`（M2） |
| D10 | BandWander | **M3**；M0 滑移已覆盖「贴墙假死」主因 |
| D11 | M1 desired 落点 | **Command.applyDesired 独占 `setGoal`**。`integrate` 只读 `_logicalGoal`（含 M0 `_stuckSteerPos`）。禁止 `setSteerGoal`，禁止 integrate 读 `_desiredPos`。M2：PathFollow **只写** `_pathSteerPos`，禁止 `setGoal`；apply 有 steer 则 `setGoal(steer)`，否则 `setGoal(desired)` |
| D12 | 到达清 desired | 到 `_logicalGoal`（≤ ARRIVE_EPS）只 `clearGoal`。**仅当**平面距 `_desiredPos` ≤ ARRIVE_EPS 才清 `_desiredPos`（终局）。中间路点不得清 desired，否则 Wander Idle / ScriptGoal 提前 Auto。见 D17 |
| D13 | SetMoveGoal ≠ Resume | ScriptGoal **到达 → Auto**。`timeoutSec` 有值：到期未到也回 Auto。缺省 timeout：未到达就一直 ScriptGoal。**Resume 只用于 Pause → Auto**。到点后 Ranger 从冻结的 state 继续（覆盖前 Chase 则仍可能 Chase），不强制回巡逻 |
| D14 | 锁窗中的命令 | **接受写入**（`SetMoveGoal` 等返回 true），冻结 tick 超时、不 integrate。落地后按当时 `_driveMode` 走。**不清 `_driveMode` / `_desiredPos`**。与 Pause 活过击飞同一套 |
| D15 | EnemySim 门控 | 有 entity 就 Command.tick →（**仅 Auto 且 isRanger** 才 `RangerAi.step`）→ PathFollow.tick → applyDesired → integrate；循环后 `flushCompute`。禁止再用 `isRanger` 包住整段移动 |
| D16 | 双端签名 | `SystemEnemy` 五 API 服务端权威；客机 stub **同名同参**，返回 false / nil，不写 Store |
| D17 | 路点到达 | PathFollow：距当前路点 ≤ **2 stud** 则推进（对齐 Ranger 节流）；跳过起点；Jump 当 Walk。贴近终局后清 `_pathSteerPos`，apply 改打 desired。Motion **不读** `_pathSteerPos`。不把 `AgentRadius` 当推进半径（大切门框） |
| D18 | Compute 配额 | `tick(rec)` 只跟路点 + 入队（同 id 已 pending 不重复）。`flushCompute()` **仅** `EnemySim.step` 实体循环之后调一次。禁止在每个 rec 的 tick 里 spawn。`PathFindUtil.compute` **会 yield**；`EnemySim.step` 栈内禁止调用。每次 spawn 内自建 `CreatePath`（M2 不做池；禁止并发共用 Path）。回调：`alive` 且 `_pathGen` 匹配才写；失败 backoff 0.5–1.5s，steer 空 → 直线 + M0 |
| D19 | 谁寻路 / usePath | Pause：不入队，清 `_pathSteerPos`。ScriptDir：**不寻路**。Auto：跟 `寻路启用`。ScriptGoal：`寻路启用` 且 `usePath ~= false`（`nil`/`true` 都寻路）。`SetMoveGoal` 写入 `_pathWanted`；**回 Auto 时清掉**。Follow 见模式/终点变化自行 `invalidate`。直线可达：Ground 中心射线无挡即跳过 Path；`直线可达跳过寻路距离`：`≤0` 关闭启发式，`>0` 启用（不再当「超过就强制 Path」） |

## 4. 架构

### 4.1 意图分层

```text
最终世界目标 desiredPos / desiredDir
        ▲
        │  M1 LogicalMoveCommand（Pause：apply 清积分点，保留 Ranger desired 供 Resume）
        │  否则 RangerAi（只写 _desiredPos）
        │
        ▼
M2 LogicalPathFollow.tick：写 _pathSteerPos（当前路点）；禁止 setGoal
        │
        ▼
applyDesired：独占 setGoal(_pathSteerPos 或 _desiredPos)；Pause / 无 desired 则 clearGoal
        │
        ▼
LogicEntityMotion.integrate（只读 _logicalGoal + M0 滑移；到积分点不清 desired，见 D17）
        │
        ▼
EnemyLogicalStore.cframe → Sync 20Hz
循环结束后 LogicalPathFollow.flushCompute()  — D18
```

**字段约定（挂 `rec.entity`，避免 Store 结构膨胀）：**

| 字段 | 写入方 | 含义 |
|------|--------|------|
| `_driveMode` | Command | `"Auto"` / `"ScriptGoal"` / `"ScriptDir"` / `"Pause"`；缺省视为 Auto |
| `_desiredPos` | AI 或 Command | 世界最终点（Y 可忽略） |
| `_desiredDir` | Command | 平面单位方向（ScriptDir） |
| `_logicalGoal` | **仅** applyDesired → `setGoal` | 本帧积分点；业务禁止直写 |
| `_stuckFrames` / `_stuckSteerPos` | Motion | M0 卡住计数与临时侧向点 |
| `_pathSteerPos` | PathFollow | 本帧路点；apply 优先于此；Pause / 无路径 / 已近终局则为空 |
| `_path` / `_pathIndex` / `_pathGen` | PathFollow | 路点缓存、当前下标、代数（过期 Compute 丢弃） |
| `_pathWanted` | Command（SetMoveGoal） | `false` 时 ScriptGoal 不寻路；回 Auto 必须清掉 |
| `_needRepath` | Motion 写 / Follow 消费 | 卡住后请求重寻路 |

Ranger **禁止** `setGoal` / `clearGoal`。PathFollow **禁止** `setGoal`。无 steer 时 applyDesired 即 desired→goal 的直线落点。

### 4.2 EnemySim 步进（目标形态）

```text
for each rec:
  if Airborne.step then continue
  if Displace.step then continue
  if airLocked or moveLocked then
    clearGoal（不清 _driveMode / _desiredPos）；命令计时冻结；continue
  end
  LogicalMoveCommand.tick(rec, dt)      -- ScriptGoal 到点/超时 → Auto；ScriptDir 写前瞻点
  if Auto and Ranger then
    RangerAi.step → 只写 _desiredPos
  end
  LogicalPathFollow.tick(rec, dt)       -- 写 _pathSteerPos；入队；禁止 yield
  LogicalMoveCommand.applyDesired(rec) -- 独占 setGoal(steer 或 desired) / Pause 则 clearGoal
  LogicEntityMotion.integrate(rec, dt)
end
LogicalPathFollow.flushCompute()        -- D18：每帧全局最多 N 次 task.spawn ComputeAsync
Sync.tick
```

M0 / M1 已完成。M2 按上序接 PathFollow；`flushCompute` 不得放进每个 rec 的 `tick`。

### 4.3 模块与路径

| 模块 | 路径 | 职责 |
|------|------|------|
| LogicEntityMotion | 现有；M0 已改 | 滑移积分、卡住；**不**导出 setSteerGoal |
| LogicalMoveCommand | `ToolSystem/LogicalMoveCommand.luau` | 模式、超时、applyDesired |
| LogicalPathFollow | `ToolSystem/LogicalPathFollow.luau` **M2 新建** | 配额队列、路点、失败回退 |
| PathFindUtil | `ToolSystem/PathFindUtil.luau` **M2 新建** | 对 `PathfindingService` 的无状态封装（compute 会 yield） |
| RangerAi | 现有；M1 改写口 | 只写 `_desiredPos`；Wander/Chase 节流看 desired |
| EnemySim | 现有；M1 插 tick | 顺序见 §4.2 |
| SystemEnemy | 现有；M1 五 API | `PauseMoveAi` / `ResumeMoveAi` / `SetMoveGoal` / `SetMoveDir` / `GetMoveDriveMode` |
| UtilsSystem | 注册新键 | 文件名 = 键名 |

**分层：** 全部 ToolSystem 仿真层；不绑 Remote、不碰 UI、不写 DataStore。  
关卡脚本经 **SystemEnemy 公共 API**，禁止业务直接改 `entity._logicalGoal`。

### 4.4 沿墙滑移（M0 算法）

本帧期望位移 `dir * step`：

1. `allowed = clampStepByWall(dir, step)`（现有 3 射线）。  
2. `allowed >= MIN_MOVE_STEP`：沿 `dir` 走 `allowed`（可短于期望，属擦墙减速）。  
3. 否则取切向 `t = (-dir.Z, 0, dir.X)` 与 `-t`，选 **墙法线侧更空** 的一条（各打 1 条短射线或比较左右 hit 距离）。  
4. 对切向再 `clampStepByWall`，能走则滑；否则本帧位移 0，`_stuckFrames += 1`。  
5. **到达**（距离 ≤ ARRIVE_EPS）才 `clearGoal`。  
6. `_stuckFrames >= STUCK_FRAMES`（建议 20～45，约 0.3～0.75s）：横向偏移 desired / 清空当前路点请求重寻路；**然后清零计数**。禁止每帧随机乱跳。

浮空/击退路径继续用现有 `clampStepByWall`，**不必**滑移（受击应被墙挡住）。

### 4.5 寻路配额（M2）

```text
全局队列 pendingCompute: { recId, dest, gen, start, agentParams }
tick(rec)：跟路点 / 入队（同 id 已 pending 则跳过）
EnemySim.step 实体循环结束后 flushCompute() 一次：
  弹出最多 寻路每帧计算数（默认 3，钳制 0～8）
  task.spawn → CreatePath + ComputeAsync（每次自建 Path）
  回来后若 rec.alive 且 gen 匹配 → 写入 waypoints
```

| 触发重算 | 条件 |
|----------|------|
| 新 desired | 与上次 path 终点平面距 > `REPATH_DEST_EPS`（建议 4～8 stud） |
| 卡住 | Motion 发出 `_needRepath` |
| 超时 | 路点跟随超过 `PATH_MAX_AGE`（建议 3～6s） |
| 失败退避 | `PATH_FAIL_BACKOFF`（建议 0.5～1.5s）内不再投递 |

直线可达（D19）：Ground 中心射线（长度=平面距）无挡 → 不请求 Path。  
`直线可达跳过寻路距离`：`≤0` 关闭启发式；`>0` 启用（默认 12 表示开着，**不是**「超过就强制 Path」）。

## 5. 公开 API 草案

> 实现以代码注释为准；关卡只应打 SystemEnemy，不打 Ranger / Motion 内部字段。

### 5.1 SystemEnemy（M1 起）

```lua
-- 暂停 AI； displace/air 锁结束后仍保持 Pause，直到 Resume
SystemEnemy.PauseMoveAi(id: number) -> boolean

SystemEnemy.ResumeMoveAi(id: number) -> boolean

-- 覆盖走点；到达 → Auto；timeoutSec 有值则到期未到也回 Auto；缺省 timeout 则一直走
-- 到达回 Auto 不是 Resume；Resume 只解除 Pause
SystemEnemy.SetMoveGoal(id: number, worldPos: Vector3, opts: { timeoutSec: number?, arriveEps: number?, usePath: boolean? }?) -> boolean

-- 按方向走 durationSec；到期回 Auto
SystemEnemy.SetMoveDir(id: number, flatDir: Vector3, durationSec: number) -> boolean

SystemEnemy.GetMoveDriveMode(id: number) -> string?  -- Auto / ScriptGoal / ScriptDir / Pause
```

`usePath`：M2 起写入 `_pathWanted`。`nil` / `true` 且 `寻路启用` → 寻路；显式 `false` → 直线。回 Auto 清 `_pathWanted`。失败（未启用 / 无 rec / 已死亡 / 非法参数）返回 false。  
锁窗内 **仍返回 true**（写入模式与 desired，落地再生效）。客机 stub 恒 false / nil。

### 5.2 LogicalMoveCommand

```lua
LogicalMoveCommand.setMode(rec, mode, payload?)
LogicalMoveCommand.tick(rec, dt)        -- ScriptGoal 到点/超时 → Auto；ScriptDir 写前瞻点
LogicalMoveCommand.applyDesired(rec)    -- 独占 setGoal(steer 或 desired)；Pause 或无 desired 则 clearGoal（不清 _desiredPos）
LogicalMoveCommand.shouldSkipAi(rec) -> boolean
LogicalMoveCommand.getMode(rec) -> string
```

`ScriptDir`：每帧 `_desiredPos = pos + dir * LOOK_AHEAD`（LOOK_AHEAD 建议 3 stud），交给 apply，避免无限远 goal。  
Pause **保留** `_desiredPos`（Resume 后 Wander/Chase 可续）；ScriptGoal/Dir 结束回 Auto 时清掉脚本点，再交给 Ranger 写。

### 5.3 LogicalPathFollow（M2）

```lua
LogicalPathFollow.tick(rec, dt)           -- 把最终 desired 落到当前路点（供 applyDesired）；投递 Compute
LogicalPathFollow.invalidate(rec)         -- 卡住 / 命令切换
LogicalPathFollow.getDebug(rec) -> table  -- 深拷贝；路点数、pending、lastStatus
```

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| ComputeAsync 卡服 | 配额 + spawn；失败 backoff；直线回退 |
| 路点抖动 / 来回重寻路 | REPATH_DEST_EPS；Chase 目标节流（Ranger 已有 goal 2 stud 节流，desired 应对齐） |
| NavMesh 未bake / 场景不在可导航层 | 直线回退；手测清单写明「场景须可导航」 |
| Ranger 与 Command 双写 goal | M1 单一 `_desiredPos`；CR 拒绝业务写 `_logicalGoal` |
| 滑移贴墙滑动过远 | 切向步长 ≤ 本帧剩余 step；单帧不沿切向超过原 step |
| 范围膨胀成关卡系统 | API 只控单 id 移动；波次/刷怪仍禁止 |
| 与 C1 抢 entity 字段 | Attacking 用独立 `state`/`timers.attackCd`；不复用 `_driveMode` |
